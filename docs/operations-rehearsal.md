# autoJEBI 운영 리허설 체크리스트

이 문서는 M14 이후 운영 투입 전에 실제 또는 준실제 공고 3건으로 확인할 흐름을 정리한다. autoJEBI는 서류 준비와 검토 보조까지만 수행하며, 실제 G2B 투찰 클릭, 금액 입력, 최종 제출 자동화는 포함하지 않는다.

## 리허설 대상

- 공고 3건: HIL/SW/전력전자 장비 성격이 서로 다른 건으로 선택
- HWP 템플릿 2종: 입찰양식, 제안서
- 회사 프로필 1건: `company_profiles.profile_key=default`
- HWP Worker: Windows `milim-hwp-agent` `/document/put-fields` 연결

## 실행 순서

1. 공고 저장
   - G2B 검색 또는 KJEBI 메일 paste로 공고를 저장한다.
   - 공고번호, 공고명, 기관, 마감일, 예가가 화면에 표시되는지 확인한다.

2. 분석과 그레이딩
   - 공고 분석을 실행한다.
   - 3축 그레이딩을 실행한다.
   - 사양/자격/가격 점수와 위험 메모가 검토 가능한지 확인한다.

3. 첨부와 서류 분석
   - G2B 첨부 가져오기를 실행한다.
   - 서류 분석을 실행한다.
   - 필수 서류 누락과 준비 상태가 문서 패널에 표시되는지 확인한다.

4. 규격 추출
   - 규격 항목 추출을 실행한다.
   - 검토 우선순위, 출처 파일, source text가 검토자에게 충분한지 확인한다.

5. HWP 생성
   - `/admin`의 HWP 필드 매핑에서 템플릿 경로와 필드명을 확인한다.
   - 입찰양식 HWP 생성을 실행한다.
   - 제안서 HWP 생성을 실행한다.
   - `required_missing`, `remaining_placeholders`, `review_status`가 화면에 보이는지 확인한다.

6. 제안서 Agent
   - 요구사항 분석, Evidence 검색, 초안 생성, 검증을 순서대로 실행한다.
   - 제안서 준비도 패널에서 coverage와 근거 없음 항목을 확인한다.
   - Evidence 없는 문장 또는 `[검증필요]` 표기가 승인 전에 남아 있는지 확인한다.

7. 사람 검토
   - 생성 job을 승인 또는 반려한다.
   - 반려 사유가 저장되는지 확인한다.
   - 최종 제출 준비 판단은 담당자가 수동으로 내린다.

## 통과 기준

- 공고 3건 모두 저장부터 제안서 초안까지 흐름이 끊기지 않는다.
- HWP Worker 미연결 또는 HWP 필드 누락 상황에서도 사용자에게 보이는 실패/경고 상태가 남는다.
- 필수 누락, 남은 placeholder, 제안서 근거 없음 항목이 숨겨지지 않는다.
- 생성물 다운로드는 가능하되 경고 상태가 유지된다.
- 실제 G2B 제출 단계로 자동 이동하는 기능이 없다.

## 기록할 항목

- 공고번호
- 실패한 단계와 오류 메시지
- 사용자가 직접 고친 필드명 또는 context path
- HWP 템플릿 내부 필드 누락
- 제안서 근거 부족 요구사항
- 운영 체크리스트에 추가할 반복 작업
