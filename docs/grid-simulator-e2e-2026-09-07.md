실제 투찰·금액 입력·제출·외부 알림 전송은 하지 않았다. 실제 공고의 참가 결정은 미결정, 제출 준비는 미완료로 유지했다.

실제 공고에는 수동 원문 요구사항을 **1개만** 등록했다. 전체 규격 추출 완료로 해석하지 않는다.
등록 내용은 규격서 1쪽의 `실시간 HIL 시뮬레이션 본체 3대 기반의 분산 연산 구조`를 직접 렌더링해 대조했다.
회사·제품 근거, 제안값, 충족 판정은 만들어 넣지 않았다.

## 발견한 보완 사항

1. **첨부 중복과 전환 연결 공백**: 기존 첨부 수집 후 v2 초기화 시 파일 4개가 있어도 공식 슬롯 연결은 0개였다. v2 수집 결과를 반영하면 연결은 복구되지만 문서 8개가 남는다. SHA256은 4종이고 각 2개씩 중복이다. ZIP에도 같은 원문이 두 번 포함된다. 기존 ID/출처/슬롯을 보존하는 정규화와 화면 대표 문서 처리가 필요하다. 이력 삭제로 해결하지 않는다.
2. **SKU 추천 품질**: HIL 실시간 시뮬레이터 요구에 RESIBLOC/ABB/GEAFOL 변압기와 MNS 배전반이 약 88% 유사도로 노출됐다. 적합성 대기 표시는 있으나 검색 유사도가 제품 적합도로 오인될 수 있다. 제품군 필터, 한국어 검색 품질, 후보 없음 처리 및 실제 HIL 카탈로그 검증이 필요하다. 정확한 원인은 이번에 확정하지 않았다.
3. **검토함 통합 누락**: `/reviews`는 기존 `listHwpJobs`를 조회한다. v2 HWP 차단 및 Excel 반려/패키지 이력이 이 화면에 없다. `frontend/src/app/reviews/page.tsx:16`, `api/routers/documents.py:51`을 확인했다. v2 작업을 포함하는 조회 또는 별도 검토함 명칭/연결이 필요하다.
4. **공고 원문의 잘못된 증빙 추천**: 공고 PDF에 `business_registration (0.95)`가 표시됐다. 실제 회사 증빙 승인으로 연결되지는 않았지만 오해를 유발한다. 원문 역할의 추천 제한 또는 명확한 요구서류 탐지 표현이 필요하다.
5. **진입 시 가짜 장애 표시**: 페이지 로딩 중 잠시 `작업 실행기 응답 확인 필요`와 `검토 시작`이 노출된 뒤 기존 작업대로 바뀐다. 로딩·미초기화·장애를 분리해야 한다.
6. **오류의 다음 행동 부족**: HWP Worker가 오전에는 `recovery_required=true`였는데 화면은 일반적인 미연결 문구만 보였다. 실제 복구 필요, 인증 누락, 템플릿 부재를 구분해서 안내해야 한다. 안전 잠금은 해제하지 않았다.

## 자동 검증

- 백엔드 안전/작업대/그레이딩/HWP 관련 6개 파일: **328 통과, 4 skip**. 전체 백엔드 스위트는 이번 회차에 실행하지 않았다.
- 프론트 단위: **146 통과, 21개 파일**. 최초 sandbox 실행은 `spawn EPERM`으로 시작 실패했고, 승인된 환경에서 재실행하여 통과했다.
- 추가 브라우저 E2E: **3 통과, 29.0초**. 합성 공고로 참가 결정 보존, Excel 다운로드, HWP 차단, 390px 화면 가로 넘침, 오래된 검토 충돌, 반려 후 재생성, 파일 업로드/공식 첨부 연결/본문 등록을 검증했다. 실제 공고의 HWP 생성 성공으로 계산하지 않는다.
- 프론트 타입 검사: **통과**, 오류 없음. 중단된 이전 실행을 통과로 계산하지 않고 재시작 후 실행 결과를 사용했다.
- 오후 검증 환경 API PID 87684, 감독 프로세스 PID 33424, 프론트 PID 98732로 재시작했다. 실제 공고 15개 작업의 기록과 미결정/미완료 상태가 유지됐다. 처리 중 작업의 강제 종료 복구 시험과는 구분한다.

## 미검증 및 다음 조건

실제 LLM 분석, 실제 HWP PutFieldText 생성/필드·한글·표·페이지 확인, 회사·제품 증빙의 진위 확인, 원문 전체 규격/자격 대조가 남았다.
실제 공고에 임의 참가/승인 결정을 넣지 않았다. 관리자 템플릿 생성·삭제와 공용 Qdrant 인제스트를 실데이터에 수행하지 않았고, KJEBI 원문 메일도 제공되지 않아 실제 메일 입력은 시험하지 않았다.
HWP Worker는 오전에 복구 잠금 상태였고, 오후 재시작 시 8000 포트가 닫혀 있었다. 필수 회사값과 실템플릿도 미확인이다.
키나 회사 증빙을 임의 작성하거나 안전 잠금을 해제하지 않았다. 실제 3건의 담당자 대조 및 실파일 검증 전에는 실무 완료/운영 전환으로 표시하지 않는다.
