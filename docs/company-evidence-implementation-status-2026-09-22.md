# 회사 증빙·실무 평가 실행 기록 — 2026-09-22

전체 목표는 미완료이며, 현재 실제 자료·담당자 확보가 필요한 선행 조건에서 차단되어 있다.
이번 기록은 첫 실행 단위의 구현 근거이며 전체 계획 완료 보고가 아니다.
사용자 확인: 실무 담당자·실제 증빙 **확보 전**. 기준선·실제 스캔 전사 승인·5건 실무 평가는 수행하지 않았다.

## 구현 근거

- `api/workspace/readiness_issues.py`: 사유 코드·대상·메시지 매개변수·해결 동작 계약 및 호환 투영.
- `api/workspace/readiness.py`: 기존 입력 준비/마감/파일 검사 이동. 기존 판정 의미 유지.
- source_inventory/source_needs/forms/output_plan/asset_policy: 판정 시점부터 코드를 반환하며 문자열은 렌더링만 함.
- `service.blockers`는 투영 한 줄만 유지. 작업대는 사유 목록과 확인 시각을 추가 반환.
- verify 결과와 package manifest/missing.txt/result는 같은 사유에서 생성. 원본/승인 입력은 수정하지 않음.
- `WorkspaceReadiness.tsx`: 서버가 만든 사유/다음 조치/확인 시각/입력 버전 표시, 과거 응답 fallback 유지.
- Python/TypeScript 계약 및 OpenAPI 스냅샷 갱신. DB 변경 없음.
- `tools/company_pilot.py`: 실제 관찰 입력 검증, 기준선 이후 목표 고정, A 이후 검증 릴리스 고정,
  불완전 자료의 미통과, 안전/시간 중단, 원본·분모·버전 변경 거부, A와 검증 사례 별도 집계.
- [ADR 0003](adr/0003-readiness-issues-and-pilot-protocol.md), [측정 사용법](company-pilot-runbook.md).

## 후속 보완 — 기존 분류 계약과 미확인 비율

- `asset_catalog.py`가 기존 분류 코드 9개, 한국어 표시명, 자료 역할을 한곳에서 관리한다.
  중앙 자료의 역할 결정과 목록 응답이 이를 사용한다. 새로운 증빙 분류나 추천 규칙은 만들지 않았다.
- `GET /v2/company-assets`에 `category_catalog`를 추가했다. 화면의 독립 한국어 분류 목록을 제거했다.
  카탈로그가 없는 과거 서버/잘못된 응답에서는 원본 조회·다운로드를 보존하며 등록·분류 수정은 재조회가 필요하다.
- 참고 제안서는 `company_reference`, 제품 자료는 `product_evidence`로 유지한다.
  카탈로그 조회 전후 회사 자료·입력 버전·공고 검토 이력이 바뀌지 않는 회귀를 추가했다.
- 측정 기록에 `confirmation_required_fields`와 `readiness_reason_counts`를 추가했다.
  채워진 칸 수와 별개이며 코드별 주된 사유 합계가 확인 필요 항목 수와 일치해야 한다.
  기준선 미측정이면 목표를 고정할 수 없고, 개선 결과 미측정이면 성공으로 평가하지 않는다.
  실제 측정 폴더의 빈 템플릿에만 새 null 필드를 추가했고 관찰값·담당자·목표는 입력하지 않았다.

브라우저 검증은 합성 API 응답을 쓰므로 실회사 자료 연결·실한글 배치·운영 준비가 완료됐다는 근거가 아니다.
기존 React act 경고, Starlette deprecation, Qdrant 버전 확인 경고가 있으나 위 테스트 실패는 없었다.

후속 변경 검증: 회사 분류/기존 자료 보관소/측정/인증/OpenAPI/아키텍처 **70건 통과**,
회사자료 UI **6건 통과**, 회사자료 브라우저 흐름 **2건 통과**.
ruff·lint-imports·ESLint·TypeScript 검사와 후속 프로덕션 빌드도 통과했다.

## 선행 조건 재점검

세 번째 목표 작업 차례에서 현재 측정 폴더를 다시 읽어 확인했다.
이전 차례는 분류 카탈로그와 미확인 비율 구현으로 진척이 있었으나, 사용자에게 확인한
담당자·실제 자료 미확보 조건은 세 차례에 걸쳐 계속 남아 있다.

| 현재 파일에서 확인한 항목 | 결과 |
|---|---|
| 담당자 이름이 기록된 역할 | 0 |
| 선정 공고번호가 입력된 사례 | 0 |
| 원본 해시 집합이 기록된 사례 | 0 |
| 기준선 측정 | 0건 |
| 목표 확정 | false |
| 고정 프로토콜/검증 릴리스 | 없음 |
| 개선 측정 | 0건 |

계획의 T04는 T01(5건 선정·기준선)에 의존하고, T08은 T07(실제 공고 A의 전체 흐름 확인)에 의존한다.
T10/T11은 가치 평가 결과에 따라 진행한다. 이 선행 조건을 대신할 실제 관찰을 생성하거나
합성 증빙으로 채우지 않는다. 독립적으로 진행한 T03, 측정 도구, 기존 분류 통합은 보존한다.

재개 입력은 실제 자료를 판독할 담당자와 가용 시간, 검토 가능한 최소 회사자료의 접근 경로다.
계획에서 요구한 스캔 실적증명/직인 계약서와 표 형식 재무 자료를 확보하면 공고 5건 선정 및
회사자료 목록을 함께 확정하고 기준선을 측정한다. 전체 회사 문서를 미리 모두 등록할 필요는 없다.
