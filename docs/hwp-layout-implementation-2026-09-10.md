## 구현 범위

- 원문 읽기, 새 템플릿 제작, 입력, 저장, 재열기, 페이지 이미지를 Worker 단일 큐/전역 mutex에서 실행한다. 별도 직접 COM 작성기는 제거했다.
- 새 문서는 FileNew와 활성 문서 수 확인 이후에만 열린 것으로 처리한다. 각 COM 호출 직전 작업번호/단계/시각/호출명만 기록한다.
- 실행 시간 초과는 신규 요청을 차단하고 미시작 요청을 취소한다. 늦은 성공·재시작으로 복구 표식을 지우지 않는다. 해시 기반 복구 CLI와 이전 파일/표식을 보존한다.
- `0015_hwp_render_mode`는 기존 템플릿에 `fields` 기본값을 유지하고 `proposal_layout_v1`만 추가 허용한다. downgrade 가능하다.
- markdown-it-py로 제목·문단·순서/비순서 목록·강조·표·명시적 페이지 나눔을 파싱한다. 미지원 요소는 생성 전 거부하고 HTML/스크립트/원격 자산은 실행하지 않는다. 링크 주소는 텍스트로 보존한다.
- 본문을 한 필드에 몰아넣지 않고 `body_0000` 등의 결정적 물리 필드로 분해한다. `proposal.body` 대응표와 요소별 해시를 저장하고 모든 저장값을 대조한다.
- `/document/create-template`은 인증·허용 폴더·덮어쓰기 금지를 적용한다. 최초 등록 CLI도 이 endpoint만 이용한다.
- 활성 템플릿 선택, Worker 진행/복구 상태, 생성 결과 및 페이지 미리보기를 v2 화면에 연결했다. 페이지 다운로드는 작업 성공 여부, 경로와 해시를 검사한다.
- HWP 다운로드의 기본 text/plain 응답을 application/x-hwp로 수정했다. 파일 잠금/읽기 오류는 문서를 닫고 권한을 확인하라는 409 오류와 다음 행동을 반환한다.

## 남은 확인과 범위 제한

- 담당자의 내용·계약·증빙·배치 승인은 아직 없다. 회사 증빙과 미검증 주장 해결 전 제출 준비 완료로 취급하지 않는다.
- PNG 가장자리 검사는 명백한 페이지 밖 잘림을 잡는 보조 장치다. 모든 폰트 대체·셀 안 겹침·인쇄기 차이를 자동 인증하지 않는다.
- 긴 표의 반복 머리글은 설정과 mock으로 검증했다. 이번 실제 문서의 표는 각 페이지 내에 들어가므로 여러 페이지에 걸친 대형 표의 반복 동작은 추가 실파일 사례가 필요하다.
- 기존 `bid_form`/`proposal` 템플릿과 매핑은 보존했다. 두 기존 양식 전체 및 공고 3건의 운영 리허설 완료를 뜻하지 않는다.
- 추가 유료 LLM, 자동 프로세스 강제 종료, 레지스트리/보안 우회, 실제 투찰·제출은 수행하지 않았다.
