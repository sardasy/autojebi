# 실무 안정화 목표 진행 기록

전체 목표는 진행 중이다. 아래 일부 회귀 통과를 HWP 실생성 또는 조직 운영 준비 완료로 해석하지 않는다.

## 이번 변경과 증거

### HWP 저장값 유실

- 조사 대상: `d3bd7871-199f-4c4a-9a17-fc2c530bb789`의 실패 `draft.hwp`와 작업용 템플릿. 원본은 변경하지 않았다.
- 설치된 `hwp5.binmodel.Hwp5File`로 BodyText/Section0를 읽었다. 두 번째 문단의 첫 텍스트와 다음 텍스트 사이 누름틀은 시작/끝 제어만 있고 실제 줄바꿈이 없었다. 전체 미리보기 텍스트에서도 시험 표시와 다음 문장이 붙었다.
- `compile_markdown`은 같은 위치에 독립된 `\n` 값을 생성하고, 기존 COM 코드는 이를 그대로 PutFieldText에 전달한다. 실제 파일에서 줄바꿈 유실은 확인됐지만, CRLF 보정 후 실생성 성공은 아직 검증하지 못했다.
- `field_text.wire_text`를 통해 입력을 CRLF로 변환한다. 원본 입력값은 변경하지 않고 저장 후 LF/CRLF 동등성만 비교한다.
- 공백, 탭, 빈 문단, 숫자, 부정 표현을 삭제/축약하지 않는다. 빈 값과 줄바꿈의 불일치를 성공으로 만들지 않는다.
- Worker 오류 응답에 필드 인덱스/반복 번호, 길이, 개행·탭 개수, 첫 차이 위치를 추가했다. 필드명/본문/부분 문자열/내용 해시는 진단 응답에 넣지 않는다. 기존 API의 작업 오류까지 이 진단을 전달하는 확장은 남아 있다.
- 기존 단일 COM 큐, 시간 초과 후 차단, 실패 파일 보존과 복구 정책은 유지한다.

### 업무 동선

- 서류 확인 탭 진입, 입력 버전/템플릿 변경, HWP 작업 상태 변경 시 읽기 전용 필수조건을 자동 조회한다. 생성이나 분석은 자동 실행하지 않는다.
- 요약과 HWP 차단 사유를 접힌 상세 밖에 표시한다. 늦게 도착한 이전 입력의 점검 결과는 무시하고 수동 새로고침 실패 시 이전 허용 결과를 지운다.
- 요구사항 0개이면 누락 검사 실행 대신 안내와 `원문 기반 요구사항 등록` 버튼을 표시한다. 버튼은 원문 검토 탭에서 상위 접힘 영역과 등록 폼을 함께 연다.
- 파일 확장자 오류를 한국어로 안내하고 서버 설정의 허용 형식을 표시한다. 파일명은 오류 메시지에 재출력하지 않는다. 파일 선택기의 형식 제한은 아직 추가하지 않았다.
- 현재 `3002` 화면에서 자동 점검 요약과 원문 등록 버튼 이동/폼 노출을 확인했다. 입력 버전 11, 시험 초안 5개는 그대로 유지했다.

## 검증

- 관련 백엔드 198 passed / 4 skipped. 추가한 HTTP 진단 응답 테스트 별도 1 passed.
- 프론트 전체 31 files / 188 passed. 일부 기존 비동기 테스트의 act 경고는 남아 있다.
- `npm run typecheck` 통과.
- 변경 HWP/업로드 모듈 및 관련 테스트 Ruff 통과.
- 전체 백엔드/모든 mock E2E/모바일 조판은 이번 변경 후 아직 재실행하지 않았다.
- HWP Worker는 복구 차단 상태이며 새 코드로 재시작하지 않았다. 식별된 PID 87168, Python 3.11.9, 생성시각 2026-09-10 18:57:36. 해당 Worker만 종료·복구할 승인을 요청했다. 승인 후에도 PID/경로/생성시각/진행 작업을 다시 확인해야 한다.
- 운영 3000/8001은 변경하지 않았다. 업로드 서버 메시지 변경은 테스트로 검증했으며 실행 중 API 재기동은 아직 하지 않았다.

다음 작업은 승인된 HWP 복구 후 CRLF 입력의 최소 실생성 및 기존 실패 초안 재검증이다. 승인 대기 중에도 첨부 처리, 중앙 자료 관리, 권한/배포 등 나머지 목표는 별도 미완료 작업으로 유지한다. 실제 회사 자료·최종 제출본·전용 서버 정보가 필요한 항목은 합성 데이터 테스트와 운영 실증을 구분한다.
