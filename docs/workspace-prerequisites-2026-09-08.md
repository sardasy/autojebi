# 필수조건 점검 구현·검증 기록

검증일: 2026-09-08. 검증 환경: Frontend 3002 / API 8002.
운영 3000/8001, 실제 회사 자격, 사람 승인, HWP 복구 기록은 변경하지 않았다.

## 구현 범위

- `GET /v2/notices/{notice_no}/prerequisites?template_key=bid_form|proposal`: 입력 버전, 선택 템플릿, 확인 시각, 조건별 상태와 다음 행동 반환.
- 공고 원문 전체 확인, 원문에서 추출된 필수 참가 자격, 회사 증빙, 제품 근거, 기존 작성자료를 구분한다.
- 자격 확인에는 유효한 원문 인용·확인된 회사/제품 증빙·담당자의 충족 판단이 필요하다. 기존 작성자료나 공고 원문을 회사 증빙으로 인정하지 않는다.
- HWP 필수 작성값, 허용 폴더의 실제 템플릿 문서 구조, Worker 인증·연결·복구 필요 상태를 각각 표시한다.
- 상태 조회는 1회 읽기 전용 요청이다. COM 실행·복구 기록 해제·자동 생성·외부 제출을 하지 않으며 원격 오류 본문이나 토큰을 반환하지 않는다.
- HWP 초안 요청 가능과 제출 준비 완료를 구분한다. 증빙 미확인은 초안 요청 자체를 막지 않지만 필수 작성값·템플릿·Worker 미충족은 화면에서 생성 요청을 차단한다.
- 입력·템플릿 변경 또는 재점검 실패 시 이전 확인 결과를 재사용하지 않는다. 실제 생성 API/큐의 기존 사전 차단 및 이력 기록도 유지한다.
- 자격 검토 버튼은 해당 요구사항을 펼치고 초점을 이동한다. 자료 업로드·기존 작성자료·매핑 설정은 기존 화면으로 연결한다.

## 실제 공고 확인

대상: `R26BK01706511-000`, PLECS RT Box 2 기반 실시간 시뮬레이션 및 AI 연계 데이터 분석 시스템 구축.

브라우저에서 필수조건 점검, 복구 절차 열기, 정보통신공사업(0036) 검토 바로가기, 서류 확인 탭, 템플릿 선택, 입력값 확인을 실제 클릭했다.

| 항목 | 확인 결과 |
|---|---|
| 입력 버전 | 21, 조회만 수행하여 유지 |
| 원문 | PDF 본문 확보, HWP 제안요청서 본문 미확인 |
| 자격·증빙 | 0036 등 공고 요구사항 검토 필요, 확인된 회사/제품 증빙 없음 |
| 기존 작성자료 | 등록된 비교 가능 자료 없음 |
| 입찰참가신청서 | 사업자번호·대표자명·주소 필수 작성값 누락 표시 |
| 제안서 | 필수 작성값 누락 0개여도 HWP 생성 비활성 유지 |
| 템플릿 | 허용 폴더의 유효한 실제 템플릿 미확인 |
| HWP Worker | `recovery_required=true`, 복구 확인 안내 표시 |

## 남은 실제 조건

이 기능은 필수조건의 확인·차단·보완 동선을 구현한 것이며 자격 취득이나 실파일 검증 완료가 아니다.
회사의 진짜 증빙 및 기존 작성자료 등록, 템플릿 내부 필드 삽입 및 허용 폴더 배치, 담당자의 한글 작업 종료 확인과 관리자 복구 절차가 필요하다.
회사정보 수정·템플릿 설정 이후에는 원문 동기화와 재점검이 필요하다.
템플릿 내부 필드 목록 및 생성 파일의 저장값·페이지 배치 검증은 실제 생성 후 별도로 수행해야 한다. 이번에는 HWP 생성 성공을 선언하지 않는다.
