# OpenAI 실제 호출 E2E 결과

2026-09-09 KST. 실제 OpenAI 분석·제안서 생성과 후속 서류 루프를 검증했다. **가상 PDF 샘플 검증이며 실공고 또는 HWP 전체 실연동 통과가 아니다.**

## 환경과 범위

- 화면 `http://127.0.0.1:3002`, 검증 API `8002`. 운영 `3000/8001`은 변경하지 않았다.
- 독립 테스트 공고 `E2E-OPENAI-20260909-01`, 제목 `[TEST ONLY] OpenAI 실제 호출 서류 작성 검증`.
- 로컬 `.env`에 사용자가 등록한 키, `openai / gpt-4.1-mini`, 실제 Responses API. 키 값은 기록하지 않는다.
- 검증 API와 큐 감독 프로세스를 재시작할 때 상속된 별도 OpenAI 키를 해당 실행 셸에서만 제외했다. PC 전역 환경은 변경하지 않았다.
- `output/pdf/document-loop-samples/`의 가상 원문·제품 근거·기존 제안서 PDF 3개를 사용했다. 테스트 제품 근거 확인은 이 가상 공고에만 적용했고 기존 작성자료는 참고용 미확인 상태를 유지했다.
- 실제 나라장터 검색·공고 다운로드, 실회사 증빙 승인, 실알림, 투찰·제출은 이번 검증에 포함하지 않았다.

실제 호출 job:

- 분석: `d4e55dc2-5cf8-4ce3-9738-5161759a8f66`
- 제안서: `eb1e5ae1-d1d8-4a7c-9061-81917d4989f5`
- 두 결과의 공급자는 `openai`, 모델은 `gpt-4.1-mini`, `reused_from_job_id=null`. 같은 입력 내용 해시에 총 2회 실행했다. 추가 호출·한도 초기화·실패한 다른 공고 재실행 없음.

## 테스트 수정과 재개

새 opt-in 시나리오는 `frontend/e2e/openai-live.spec.ts`, 프로젝트는 `openai-live`다. 자동 재시도는 0회다. 새 실행은 미등록 테스트 공고만 허용한다. 명시적 재개는 성공한 분석·제안서를 확인하고 기존 결과를 사용하며, 실패한 유료 제안서를 다시 호출하지 않는다. 완료 기록이 있으면 재개도 거부한다.

1. 첫 실행: 실제 분석 성공 후 제안서 API 요청이 403으로 차단되었다. Playwright API 요청의 Origin 헤더가 빠졌기 때문이다. 앱 보안 정책은 유지하고 테스트 요청에 실제 화면 출처를 추가했다. 이 시점의 제안서 유료 호출은 0회였다.
2. 첫 재개: 같은 공고에서 제안서 실제 호출 1회 성공. 페이지를 새로 연 후 검토 의견이 빈 상태여서 비교 초안 저장 버튼이 비활성화되었다. 재개 시 테스트 검토 의견 입력을 추가했다.
3. 두 번째 재개: 분석·제안서 재호출 없이 비교 작성부터 다운로드까지 완료. Playwright **1 passed (15.5s)**. 이는 최초부터 한 번에 통과한 결과가 아니라, 위 2개 테스트 입력 오류를 수정한 연속 검증이다. 초기 오류는 `result.json`에 보존했다.

간소화 화면에는 유료 제안서 생성 버튼이 없으므로 해당 단계만 명시적인 API 요청을 사용했다. 원문 분석 및 등록·비교 작성·결과 반영·검사·다운로드는 실제 브라우저 UI로 실행했다. 전 단계를 버튼으로 시연하려면 유료 생성 버튼 UX는 별도 검토가 필요하다.

최종 변경 후 프론트 타입 검사와 `tests/test_workspace_openai.py`, `tests/test_workspace_llm_usage.py` 집중 회귀도 통과했다. 이 백엔드 회귀는 mock이며 위 실제 호출과 별도다. 이번 턴에서 전체 백엔드·프론트 단위 테스트 묶음 전체를 다시 실행하지는 않았다.

## 남은 실연동 조건

- 입찰참가신청서 템플릿 파일 및 실제 필드 대조 결과가 필요하다.
- 사업자번호·대표자명·주소·기관명 필수 작성값이 비어 있다.
- 실제 회사/제품 자료, 공식 마감 정보와 담당자의 원문·요구사항 검토가 필요하다.
- Worker 접속 성공만 확인했으며 HWP 파일 저장값·페이지 배치·한글 렌더링은 미검증이다.
- 모바일에서 가로 넘침은 없지만 긴 검토 화면의 편의성과 실제 사용자 검토 품질은 별도 평가가 필요하다.
