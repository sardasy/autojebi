# 실무 작업대 UX/UI 구현 및 검증

검증일: 2026-09-06. 기존 작업 중 변경을 유지한 로컬 작업 트리 기준이며, 커밋/배포 완료를 의미하지 않는다.

## 구현 범위

- 밝은 공통 화면, 기본 공고 작업대, 검색/검토함/관리자 탐색 메뉴.
- 핵심 5열 목록, 선택형 점수/SKU 열, URL 필터/페이지, 마감일 정렬.
- 상세 5개 탭과 고정 상태/다음 작업, 기존 주소 및 문서 앵커 호환.
- 목록/상세의 규격 후보 수와 요구값 확인 수 집계 통일. 체크리스트 기반 누락/준비도 재계산, 업로드/삭제 후 갱신.
- 누락 우선 서류 행, 행별 업로드/공통 서류 연결, 규격 제안값/근거/검토 상태.
- HWP 템플릿 선택/일반 입력 폼/접힌 고급 설정, 필수 누락/미입력/작업/검토 상태.
- DB 기반 검토함 검색/필터/페이지. 실패 작업 승인 거부, 경고 승인 의견 필수, 경고 파일 다운로드 허용.
- 수동 제안서 단계 실행, 저장 섹션/근거/검증 상태 및 준비도 표시.
- G2B 키 누락/인증/시간 초과/외부 실패 메시지 구분. 과거 실행 오류가 다음 작업을 계속 차단하지 않도록 분리.
- 모달 내부 스크롤, 키보드 포커스 제한/복원, 탭 방향키 이동, 모바일 표 내부 스크롤.
- DB 구조/인증 유지. 실제 투찰/금액 입력/제출 없음. 알림은 dry-run, 그레이드 Slack 선택 기본 해제.

### 모의 E2E 범위

실제 API 라우터와 메모리 SQLite에 저장하고 G2B 검색/HWP Worker만 대체한다. 운영 DB와 분리된다. 모의 HWP 파일은 다운로드 경로 검증용이며 한글에서 열 수 있는 실제 HWP가 아니다. 업로드 PDF도 저장/연결 확인용 모의 바이트이며 PDF 텍스트 추출 품질 검증이 아니다.

1. 목록/상세 규격 후보 2개/요구값 1개 일치, 경고 HWP 생성, 의견 없이 승인 불가, 의견 입력 승인, 새로고침 후 유지.
2. Worker 실패 job, 검토함 실패 필터, 승인 비활성. G2B 키 누락 메시지. 모달 Escape 후 원래 버튼 포커스.
3. 행별 업로드 기본 체크리스트 연결, 업로드 후/새로고침 후 파일 유지. 규격 제안값 저장 및 새로고침 유지.
4. 정상 HWP 생성, 필수 누락/미입력 0건, 다운로드 성공, Excel 생성.
5. 390px에서 목록/상세/검색/관리자/검토함 페이지 가로 넘침 검사. 검색 결과 저장 후 상세 이동.
6. 저장한 공고에서 분석 실행 완료, 그레이딩 실행 완료. Slack 기본 해제 상태 확인. 외부 LLM/SKU 품질 대신 키 없는 fallback 흐름 검증.

최종 모의 E2E는 두 번 연속 2 passed(28.3초, 43.2초). 검증 중 발견한 관리자 표의 모바일 넘침, 체크리스트 업로드 선택값/갱신, 정상 HWP의 0건 표시, 반복 초기화 공고번호를 수정했다. 상단 요약도 저장된 과거 준비 플래그 대신 현재 체크리스트를 사용하도록 회귀 테스트를 추가했다.

새 모의 시나리오는 명시 opt-in이다. 기존 라이브/운영 E2E 전체 재통과를 의미하지 않는다.

## 재실행

프로젝트 루트에서 테스트 API를 시작한다. `tests/workbench_mock_app.py`는 테스트 전용이며 운영에 배포하거나 외부에 공개하지 않는다. 상태 초기화 라우트가 있으므로 반드시 루프백에 바인딩한다.

```powershell
python -m uvicorn workbench_mock_app:app --app-dir tests --host 127.0.0.1 --port 8002
```

별도 터미널에서 프론트:

```powershell
cd frontend
$env:NEXT_PUBLIC_API_BASE='http://127.0.0.1:8002'
$env:INTERNAL_API_BASE='http://127.0.0.1:8002'
$env:NEXT_DIST_DIR='.next-workbench'
npm run dev -- --hostname 127.0.0.1 --port 3002
```

검증 터미널:

```powershell
cd frontend
$env:E2E_BASE_URL='http://127.0.0.1:3002'
$env:E2E_API_BASE='http://127.0.0.1:8002'
$env:E2E_MOCK='true'
npm run e2e -- --project=workbench-mock
```

## 남은 실연동 확인

- 실제 G2B 인증키 설정 후 검색/결과 없음/저장 리허설.
- Windows HWP Worker 실행, 필드가 삽입된 양식 2종과 경로/토큰 확인 후 실제 파일 열기 및 검토.
- Qdrant 호환 버전 정렬 후 실제 SKU 검색 품질 확인.
- 기존 라이브 E2E의 전체 회귀는 환경 준비 후 별도 실행. 모의 검증을 실연동 통과로 대체하지 않는다.
