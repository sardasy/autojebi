# ADR 0003 — 제출 준비 사유의 단일 원천과 사전 고정 실무 평가

- 날짜: 2026-09-22
- 상태: 채택·구현 (사유 코드와 측정 도구). 실무 효과 검증은 미완료.
- 상위 계획: [회사 증빙·실무 평가 실행 계획](../company-evidence-evaluation-action-plan-2026-09-22.md)

## 문제

제출 준비 차단이 한국어 문자열로만 반환되어 해결 대상과 사유를 안정적으로 집계하기 어렵다.
구조화된 사유를 별도로 계산하면 기존 `blockers`와 다른 판정이 생길 수 있다.
또한 개선 결과를 본 뒤 평가 목표를 정하면 실무 가치를 공정하게 평가할 수 없다.

## 결정

1. 준비 판정은 `api/workspace/readiness.py`와 분야별 기존 검증 함수가 코드로 반환한다.
   `ReadinessIssue`는 code, scope, entity_id, blocking, message_params를 담는다.
   한국어 message와 next_action은 중앙 카탈로그에서 계산하며 입력된 표시 문구는 신뢰하지 않는다.
2. `service.blockers`는 `render_blockers(readiness_issues(inputs))`의 호환 투영만 제공한다.
   기존 순서와 문구를 보존한다. 양식별 상세 사유는 모두 보존하지만 이전 문자열 API의 양식 경고 중복 제거는 유지한다.
3. 작업대 응답, verify 결과, 패키지 manifest에 구조화된 사유와 평가 시각을 추가한다.
   기존 version/input_version에 연결하며 DB 마이그레이션과 과거 기록 재작성은 하지 않는다.
   verify와 패키지는 기존과 같이 입력 준비 조건을 계산한다. 작업대의 마감·동기화 검사와
   패키지의 생성물 경고는 실행 맥락에 맞게 같은 사유 계약으로 추가한다.
4. 파일 무결성과 만료·마감 조건은 기존 시점에 재검증한다. 조회는 승인·입력 버전을 변경하지 않는다.
   경고가 비어 있어도 자동으로 참가 결정·충족 판정·제출 준비 승인을 하지 않는다.
5. 측정은 5건의 조건 파악·요구사항 목록·증빙 검색·제출 전 검토, 그중 2건의 초안 작성/수정으로 한정한다.
   실제 담당자·시간·원본 해시 집합·독립 대조표가 준비된 뒤 기준선을 기록한다.
6. 개선 실행 전에 목표를 `protocol-frozen.json`에 고정한다. A는 개발용 관찰이다.
   A 이후 B~E의 코드·규칙 버전은 `validation-release.json`으로 별도 고정한다.
   두 고정 파일은 새로 생성만 가능하며 보고 시 해시를 확인한다. 최초 A 결과도 검증 버전에 연결한다.
7. 5건 미측정·자료 준비 비용 미기록은 성공이 아니다. 안전 실패는 가치 지표보다 우선한다.
   담당자 입력의 진실성과 파일의 사후 악의적 재작성 방지는 이 로컬 도구가 보증하지 않는다.
   이 도구는 인증된 승인 기록이나 전자서명 시스템이 아니다.
8. 제품은 실제 나라장터 투찰을 지원하지 않는다. 최종 한글 배치는 담당자가 확인한다.
9. 기존 회사자료 분류는 서버 카탈로그 하나에서 code/label/role을 반환한다.
   `category_catalog`의 해시는 표시·역할 목록의 변경 식별용이며 요구사항 충족 규칙이나 승인 해시가 아니다.
   추천 규칙은 공고 A 확인 후 별도로 설계한다. 참고자료를 증빙으로 자동 승격하지 않는다.

## 적합도 함수

- `tests/test_workspace_readiness_issues.py`: API 추가 필드와 실제 사유 노출, 조회 불변,
  추출 실패 미해결, 만료/주체 불일치/변경/비활성, 문자열 투영, 표시 문구 재계산,
  verify와 패키지 일치, Python/TypeScript 코드 일치, `blockers`에 독립 판정 금지.
- `tests/test_company_pilot.py`: 미측정 고정 거부, 기존 폴더 덮어쓰기 거부, 5건/A 별도 집계,
  미측정 미통과, 3건 지연 중단, 안전 실패 우선, 원본/분모/버전/실행 시점/중복/고정 기록 변경 거부.
- `WorkspaceReadiness.test.tsx`: 서버 사유/다음 조치와 과거 응답 호환.
- `workspace-guidance-mock.spec.ts`: 실제 브라우저 표시와 조회 중 변경 요청 0건.
- 기존 만료·마감·정정 ZIP·양식·패키지 회귀와 OpenAPI 스냅샷을 유지한다.
- `tests/test_asset_catalog.py`: 기존 분류와 역할 보존, 코드 계약 일치, 카탈로그 조회 불변,
  서로 다른 응답 간 카탈로그 오염 방지. CompanyAssets UI/브라우저 회귀는 서버 분류명 사용과 자료 연결 미승인을 확인한다.
- 측정 도구의 확인 필요 비율은 필수 항목 분모를 공유하고 사유 코드별 합계를 검증한다.
  미측정값을 0으로 바꾸거나 채워진 칸을 확인 완료로 추정하지 않는다.

## 후속 범위

스캔본 전사 주장, 불변 추출 스냅샷, 규칙 카탈로그와 근거 연결 확장은 아직 구현되지 않았다.
그 계약은 공고 선정과 최소 실제 자료 확인 후 후속 ADR/티켓에서 확정한다.
현재 exact 인용 계약을 완화하거나 회사 참고자료를 증빙으로 승격하지 않는다.
