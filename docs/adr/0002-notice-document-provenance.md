# ADR 0002 — 공고 표시 정보·ZIP 작성 대상·검토 출처

- 상태: 채택 — 2026-09-22
- 계기: R26BK01735627-000의 요약 누락, ZIP 내부 HWPX 작성 제한, HWP 진단 지연.

## 결정

1. 기존 본문과 파일 해시는 바꾸지 않는다. `extraction.presentation`은 기존 본문에 대한 문자 구간·XML 위치·내부 경로만 추가한다. 구조 위치가 본문 해시와 맞지 않으면 확정 인용으로 쓰지 않는다.
2. `notice_brief`는 서버에서 계산한 원문 탐색 보조 정보다. 값 발견 / 추출 불완전 / 자동 확인 못함 / 사람의 부재 확인을 구분한다. 추출 성공만으로 원문 부재를 단정하지 않는다. 부재 확인은 전체 원본 ID·파일/본문 해시 집합과 담당자 확인 범위·서버 신원·시각에 연결한다. 자료 추가도 확인을 무효화한다.
3. 승인 앵커는 기존 원본·본문·인용·근거·생성물 해시다. 신규 표시 정보와 표시용 대조 기록만 양식 검토 근거에서 제외한다. 추출 실패·완전성은 제외하지 않는다. 새 검토의 요약 버전·표시 항목 해시로 갱신을 안내하며, 과거 기준이 없으면 비교 불가로 표시한다. 과거 승인에 신원이나 해시를 소급 채우지 않는다.
4. ZIP 내부 작성 대상은 공고번호·부모 문서 ID·부모 ZIP 해시·내부 경로 체인·내부 해시 체인으로 식별한다. 원문 문서를 중복 등록하지 않는다. 부모 ZIP이 바뀌면 동일 HWPX라도 새 대상이며 초안·승인 자동 이관은 없다. 이전 입력/생성물은 이력에 보존한다. 현재 패키지에 이전 작성본을 포함하지 않는다.
5. 신규 자동기입은 HWPX에 한정한다. 바이너리 HWP는 수동 작성 대상이며 기존 추출과 원본 다운로드는 유지한다. 압축파일은 메모리 안에서 기존 경로·깊이·공유 용량/엔트리 한도를 적용한다.
6. 다른 형식의 동일 문서는 완전한 비어 있지 않은 전체 본문의 NFC+연속 공백 정규화 결과가 정확히 같은 경우만 자동 묶는다. 숫자·단위·구두점·순서는 유지한다. stem·유사도만으로 묶지 않는다. 사람의 동등성 확인은 양쪽 파일 해시에 연결하며 표시·집계만 바꾼다.
7. JSON 저장과 기존 `/v2` API에 선택 필드를 추가한다. DB 마이그레이션과 기존 자료 강제 재추출은 없다. JEV 원문/정책 요청 해시는 표시 정보와 무관하다.
8. HWP health는 서버 전체 3초, 브라우저 본문 소비 포함 5초, 단일 요청으로 제한한다. 정상 3초; 일시 실패 3/6/12/24/30초; 설정 오류 30초. 마지막 성공 상태와 현재 조회 실패를 구분한다. 복구 표식 해제·불확실 작업 재실행은 자동화하지 않는다.

## 자동 검증 (CI 적합도 함수)

- `tests/test_notice_document_provenance.py`: canonical 본문 불변, 중첩 ZIP·다중 section·Unicode 구간, 표현 변형/음성 사례, 부재 확인 무효화, 동일성, 정정 ZIP 대상 변경, 원본 보존·작성본 재조회.
- `tests/test_workspace_jev.py`: 표시 정보 변경 후 동일 요청 해시·작업 재사용·추가 호출 없음.
- `tests/test_hwp_health_deadline.py`, `frontend/src/lib/__tests__/hwpHealth.test.ts`: 서버 기한·민감정보 제외·상태 구분, 5초 취소·직렬화·backoff·해제 시 취소.
- 기존 승인/인용/양식/패키지/역할 테스트와 OpenAPI 스냅샷도 계속 통과해야 한다.
- `frontend/e2e/notice-provenance-live.spec.ts`: opt-in 합성 공고에서 근거 연결·저장·재열기·다운로드·패키지 출처를 검증한다. [실공고 재검증 결과](../notice-document-provenance-e2e-2026-09-22.md)는 한글 배치 미확인을 별도 기록한다.

## 한계와 운영 확인

요약은 참가자격·공급가능성 판단이나 승인이 아니다. HWPX 저장값 재조회는 실제 한글 배치 확인을 대신하지 않는다. 합성 회사 자료는 별도 테스트 공고에서만 사용한다. 마감 경과 공고는 검토용이며 실제 투찰은 자동화하지 않는다. 실공고 검증 결과는 런타임 E2E 보고서에 별도로 기록한다.
