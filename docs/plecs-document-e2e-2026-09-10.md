## 초기 오류와 수정

1. 첫 실행은 PDF 등록·추출·비교 초안 저장·검사·생성까지 성공했다. 다운로드 선택자가 첫 번째 완료 패키지를 선택하면서, 아직 화면에 남아 있던 버전 23의 이전 생성물을 다운로드했다. 받은 해시는 이전 작업 `2323ebf0-93de-4fa3-aaa9-e8194bc86fc8`과 일치했다. 새 파일 저장 오류는 아니었다.
2. 테스트가 새 생성 작업번호의 다운로드 링크를 기다리도록 수정했다.
3. 재개 중 누락 검사에서 항상 새 작업이 생긴다고 가정한 대기 로직을 발견했다. 서버는 같은 입력의 정상 결과를 재사용하고 있었다. 불필요한 대기를 중단하고, 버튼 요청의 실제 응답 작업번호를 추적하도록 수정했다. 제품의 중복 실행 방지는 변경하지 않았다.
4. 마지막 실행에서는 PDF·비교 초안을 중복 등록하지 않고 기존 정상 검사·Excel 결과를 재사용했다. 새 검토 패키지는 생성 후 정확한 작업번호로 다운로드했다.

자동 재시도는 0회이며 위 수정 후 수동 재개했다. 따라서 최초부터 한 번에 통과한 결과로 보고하지 않는다. 변경 파일은 `frontend/e2e/plecs-document-live.spec.ts` 및 Playwright 프로젝트 설정이다. 제품 기능 코드는 이번에 변경하지 않았다.

## 남은 문제

- 참고자료 PDF 15쪽 전체가 앱의 구조화된 제안서 섹션으로 자동 변환된 것은 아니다. 이번에는 납기 관련 섹션 1개만 연결했다. PDF 전체는 참고자료와 패키지에 보존했다.
- 기존 요구사항 18개는 보존했으나 요청서의 상세 기술규격 전체를 추가 등록·채택하는 검증은 하지 않았다.
- 회사 증빙·실제 제품 증빙이 없고 요구사항 및 섹션 검토가 끝나지 않아 `ready=false`다.
- HWP Worker 실가동과 템플릿 필드·생성 파일 배치는 미검증이다. 필수 회사값은 사업자번호·대표자명·주소가 비어 있으며 유효한 템플릿도 없다.
- 이전 생성물과 최신 생성물이 같은 목록에 있으므로 사용자는 입력 버전과 생성 시각을 확인해야 한다. 최신 결과 자동 포커스 및 이전 이력 접기는 후속 UX 개선 대상이다.
- 전체 백엔드·프론트 단위 스위트, 신규 G2B 검색, 유료 AI 분석·생성, 실제 HWP 출력까지 이번 결과에 포함하지 않는다.
