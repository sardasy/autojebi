# HWP 복구·템플릿 준비 실행 기록

2026-09-08. 실행 계획은 `hwp-template-recovery-plan-2026-09-08.md`다.
현재 상태는 **코드·입력 준비 완료, 실제 복구 및 HWP 파일 제작 대기**다. 전체 목표는 미완료다.

## 보존 및 현황

- 운영 3000/8001과 HWP Worker는 유지했다. 유휴 상태를 확인한 검증 작업 실행기와 API 8002만 새 코드로 재시작했다.
- 프로세스 목록에서 표식의 원래 PID 69664와 Hwp.exe가 없음을 확인했다. Windows 창 목록에서도 한글 창은 없었다. 이것을 담당자의 파일 확인이나 복구 승인으로 대신하지 않았다.
- Worker PID 32652는 실행 중이며, 과거 실패 표식이 유지되어 복구 확인이 필요하다. 표식 해시 `5dce6b6f4af75d4faf5cb6480992c24ad359322127a11e8e4b7e54224cf9629a`는 조회 당시 값이며 실제 복구 시 다시 읽어야 한다.
- `data/workspace/recovery-audit/20260908T100501896122Z/`에 표식 사본, 파일 103개의 목록·크기·해시, 관련 작업 53건, 변경 전 템플릿·매핑 설정을 보존했다. 복구 기록을 삭제하거나 해제하지 않았다.

## 구현 및 반영

- 제안서에 `proposal_body -> proposal.body`, 필수 입력, `transform=none` 매핑을 추가했다. 검증 DB에서만 누락 항목 추가 seed를 실행했으며 기존 회사정보와 수동 매핑을 보존했다.
- 전체 본문 필수 매핑이 없으면 생성 전에 서버에서 차단한다. 요약만 들어간 제안서를 전체 본문 생성 성공으로 처리하지 않는다.
- `hwp_inspect` 작업 종류를 추가했다. 기존 v2 jobs API와 영속 큐를 사용하며 DB 구조 변경은 없다.
- Worker `/document/fields` 호출 결과의 필드 목록·중복 발생 번호·해시·정상 종료 기록을 검증한다. 원격 템플릿의 실제 입력값은 검사 결과로 반환하지 않는다.
- 검사 결과를 입력 버전·템플릿 해시·매핑 해시에 연결하고, 현재 파일/매핑과 맞는 필수 필드 검사 결과가 없으면 작업대 HWP 생성 버튼을 차단한다.
- 생성 직전 실제 필드를 다시 조회한다. 필수 필드 누락이나 문서 형식 불일치는 PutFieldText 호출 전에 차단한다.
- 템플릿 검사 시간 초과는 COM 요청을 재전송하지 않는다. 불확실한 검사 실패는 HWP 생성과 동일하게 외부 상태 확인 후 복구하도록 처리했다.
- UI에 템플릿 필드 검사 버튼·실제 필드 수·필수 누락·미매핑 표시를 추가했다. 검사 결과는 파일 승인이 아니다.
