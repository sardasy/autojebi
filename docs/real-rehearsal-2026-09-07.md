## 실첨부에서 발견한 결함

소프트웨어 원문 첨부 목록은 공고 HWP, 공고 PDF, 물품명세서 XLS, SW 사양서 PDF의 4개였다.
기존 `iter_g2b_attachments`가 PDF/HWP/HWPX만 반환하므로 XLS가 결과·경고에서 모두 사라졌다. 작업은 3개 파일만 확보한 뒤 `succeeded / normal`이었다.
이는 잘못된 전체 확보 인식을 유발하므로 출시 차단 결함이다. 다운로드 실패가 아니라 지원 확장자 필터에 의한 조용한 누락이다.

기존 결과는 변경하지 않고 보존한다:

- SW 첨부 작업 `ba63244f-af2b-4e7a-8daf-646a45753192`: 3개, normal. 공식 목록 대비 불완전.
- 물품 첨부 작업 `a0879869-7ee0-409f-8d54-f3323ec83f24`: 2개, normal. 전체 원문 대조/본문 확인과는 별개.

수정 범위는 전체 공식 첨부 목록 표시, 슬롯별 다운로드 결과/경고, XLS 원본 보관, 파일 연결/본문 확보 상태, 누락 시 원문 전체 확인 및 최종 준비 차단, 수동 변환본 연결 복구다.
기존 원문·과거 작업·사람 검토 이력은 보존하며, 새 작업으로 다시 검증한다.

물품 공고의 ZIP도 이전 필터에서 조용히 제외되던 첨부였다. 첫 수정본은 2/3 확보와 ZIP 미지원 경고를 정확히 남겼고, 후속 보완에서 ZIP 원본 보관을 지원해 3/3 확보했다. ZIP은 압축 해제하거나 파일을 실행하지 않았다.
XLS를 HWP Worker에 보내지 않으며 ZIP/XLSX를 HWPX로 해석하지 않는다. 선언된 문서명과 저장 경로 확장자가 모두 해당 한글 형식일 때만 추출 경로에 진입한다.

추가한 `source_attachments`는 파일 확보·본문 확보 상태다. `ready` 값은 이 목록에서 본문 확보를 뜻하며 공고의 `ready=true`나 사람 승인과 다르다. UI는 이를 `본문 확보`로 표시한다.
공식 슬롯 번호와 URL이 모두 일치하는 공고 원문만 연결한다. 회사/제품 증빙의 같은 해시나 파일명만으로 연결하지 않는다. 변환본/과거 수동 원문은 담당자가 슬롯과 의견을 명시해 연결할 수 있으며 이전 관련 승인을 재검토 대상으로 전환한다.
