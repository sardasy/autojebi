# 작업대 E2E 재검증

대상: 검증 프론트 3002 / API 8002. 공고 R26BK01722905-000, 입력 버전 11.
운영 3000/8001, 원문, 시험 초안 5개와 기존 실패 이력은 변경하지 않았다.

## 실제 브라우저 버튼

| 동작 | 관측 결과 | 판정 범위 |
|---|---|---|
| 확인한 항목 작성하기 | 비교·작성 탭 이동. 작성 5개 / 원본 첨부 7개 / 전자 제출 1개 분리 | 통과 |
| 서약서 선택 | 정성제안서와 다른 저장 본문·원문 근거 표시 | 통과 |
| 텍스트 초안 다운로드 | 다운로드 이벤트 확인 | 파일 내용·해시 재대조는 이번 실행에서 미수행 |
| 서류 확인으로 이동 | 필수조건 자동 조회, 요구사항 0개 안내, 누락 검사 비활성 | 통과 |
| Excel 생성 | 완료·경고 표시. 기존 07:12:36 결과 재사용 | 새 파일 생성으로 집계하지 않음 |
| 검토 패키지 | 10:45:28 완료·경고 작업 확인 | 실제 작업 완료, 다운로드 내용 대조는 별도 |
| HWP 템플릿 선택 | 실무 서식으로 변경 시 자동 재점검 | 통과 |
| HWP 생성 | Worker 복구 필요로 버튼 비활성 | 실생성 차단, 통과 아님 |

시험 초안은 TEST ONLY / 제출 금지 표시와 검토 대기를 유지했다. 요구사항·증빙·초안을 승인하거나 실제 G2B 제출을 실행하지 않았다. 실제 G2B 검색과 유료 LLM은 이번 재검증에서 호출하지 않았다.

## 자동 브라우저 회귀

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:3002'
$env:E2E_API_BASE='http://127.0.0.1:8002'
npm run e2e -- --project=workbench-mock
```

- 최초: 5 passed / 1 failed / 2 skipped. workspace-guidance가 기존의 숨겨진 필수조건 버튼을 기대했다.
- 보정: 실제 필수조건 API 응답을 mock하고 자동 조회, 펼치지 않아도 보이는 차단 사유, 재확인 버튼, 새 변경 요청이 없는지 검증한다.
- 재검증: 6 passed / 2 skipped (11.5초).
- 통과: 공고 핵심 사항, 작성 대상 확인·회사자료 인용·문서별 저장·다운로드·재조회, HWP 경고/복구 차단, 인용 후보 복구, 단계 이동·자동 필수조건.
- 2개 skip은 E2E_MOCK=true 및 별도 workbench_mock_app 서버가 필요한 구형 작업대 테스트다. 실제 8002를 reset하거나 대체하지 않았다.
- 테스트는 1280px/390px에서 가로 넘침을 검사하고 frontend/test-results에 스크린샷을 남긴다.

## 품질 게이트와 남은 차단

- 백엔드 1,347 passed / 13 skipped.
- 프론트 단위 189 passed / 타입 검사 통과.
- 변경 추출 모듈과 테스트 Ruff 통과.
- 실제 HWP 저장값 불일치 수정은 복구 승인 후 재검증이 필요하다. 복구 표식을 삭제하거나 프로세스를 강제 종료하지 않았다.
- 회사 자료·필수조건 미확인과 요구사항 0개가 남아 있어 제출 준비 완료가 아니다.
- API/실행기는 추출 관련 최신 코드로 재기동하지 않았다. 이번 브라우저 실행 결과와 최신 코드 단위 검증은 구분한다.
