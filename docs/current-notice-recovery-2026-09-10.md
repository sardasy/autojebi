## 구현 범위

1. 분석 오류의 안전한 후보 보존 및 원문 위치 진단. 공백만 정규화하며 숫자·부정·단위를 수정하지 않는다. 유효 후보만 인증된 조회로 반환하고 전체 공급자 응답/토큰/내부 예외를 기록하지 않는다.
2. `adopt-requirements`는 버전·원문 파일 및 본문 해시·위치·중복방지 키를 검증한 후 원자적으로 반영한다. 기존 수동 요구사항과 실패 작업은 유지하고 채택 항목은 pending/unassessed다.

4. local/external 실행기별 PostgreSQL 잠금·선점·완료 receipt·재시작 복구·health. HWP 실행 때문에 로컬 문서 작업이 같은 큐에서 대기하지 않는다. HWP COM 큐/전역 mutex는 유지한다.
5. HWP 필드 검사 visible/operation_id, 최초 실패 단계와 종료 단계 분리, 문서 편집 가능 상태와 정리 필요 상태 분리. 시간 초과 후 복구 표식과 신규 요청 차단 유지.
6. 상단 작업 진행 추적, 후보 인용 비교 UI, 별도 원문 상태 UI, 검색 전체/필터 후 개수, XLSX 전용 MIME, 복구 요청의 작업 완료 추적.
