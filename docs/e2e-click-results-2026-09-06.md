## 이번에 수정한 결함

1. HWP 작업 목록 누락: `readDocumentAutomation`이 `hwp_jobs`를 반환하지 않아 생성/검토 패널이 숨겨졌다. 배열을 보존하도록 수정했다.
2. 실패를 일부 완료로 표시: HWP 모달이 실패 job의 존재를 생성 성공으로 취급했다. 생성 파일 유무로 판단하고, 파일 없는 failed job은 작성 불가로 표시하도록 수정했다.
3. 긴 오류 모달의 닫기 버튼이 화면 밖으로 나감: 공통 Modal에 화면 높이 제한, 고정 헤더, 본문 세로 스크롤을 적용했다. 실제 실패 결과를 유지한 채 화면과 닫기 동작을 재검증했다.

## 남은 문제

- 규격 집계 불일치: 규격 패널은 15개를 읽지만 공고 상세 API의 `spec_item_count`는 0이다. 업무 흐름에도 계속 규격 추출 필요가 표시된다.
- G2B 키 누락 상태에서 검색이 진행되고, 결과가 사용자용 원인 안내 대신 502/RetryError를 노출한다.
- 업로드 직후 사업자등록증은 준비완료인데 요약은 `1/6 준비 · 누락 6`으로 남았다. 체크리스트 상태 수정 시에는 다시 계산됐다. 업로드 이후 누락 집계 갱신 필요.
- 규격 추출 후에도 이전의 `규격 항목 추출 필요` 오류가 누적 목록에 남고, 재시도할수록 중복 오류가 증가한다. 현재 문제와 과거 이력을 구분할 필요가 있다.
- 규격 추출 완료 15개는 이번 환경에서 값 있는 원문 규격이 아니라 빈 후보 행이었다. 빈 후보 생성과 실제 추출 성공을 구분해 표시할 필요가 있다.
- 수동 raw JSON의 `org_name`/`base_price`는 정규 공고 메타데이터로 승격되지 않아 상세에서 기관/예가가 `-`로 표시됐다. 사용자 입력 안내 또는 명시적 정규 필드 입력이 필요하다.

## 확인하지 못한 범위

- 실제 G2B 결과 수신과 검색 결과 저장: 키 미설정/외부 호출 실패로 미검증.
- 실제 Claude 분석 품질: 이번에는 빈 사양 결과만 확인했으므로 실연동 성공으로 판정하지 않는다.
- 실제 HWP 파일 생성, PutFieldText 정확도, 남은 placeholder가 있는 생성물, 성공 작업 승인: Worker 미연결로 미검증.
- HWP Worker 동시 실행 직렬화와 Windows 한글 내부 작업: 이번 범위에서 실행하지 않음.
- 관리자 템플릿/필드 생성·수정·비활성화, 메일 추출, Proposal Agent 단계별 생성: 이번에는 클릭 테스트하지 않음.
- 실제 외부 알림과 실제 G2B 제출은 실행하지 않음. 파일 삭제도 실행하지 않음.
