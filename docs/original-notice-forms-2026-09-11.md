# 공고 첨부 원본 양식 작성

2026-09-12 후속: 원본 HWPX 작성본의 사람 승인·반려와 입력/파일 변경 시
재검토 경로를 추가했다. 아래 기록은 9월 11일 검토 대기 상태의 검증 이력이며,
현재 승인 계약은 [후속 검증 기록](original-form-review-2026-09-12.md)을 따른다.

## 문제와 동작

기존 문서별 작성은 자유 본문을 Markdown으로 내보냈다. 공고 제안요청서에 있는
서식 1·서식 2의 항목을 채워도 해당 표와 서식으로 출력되지 않았다.

비교·작성 화면의 ‘공고 첨부 양식 작성’에서 첨부 HWPX의 실제 작성 칸을 선택한다.
항목마다 작성 내용과 등록된 회사 자료 인용 또는 노션·웹 주소/발췌문을 함께 저장한다.
기존 작성 본문과 발췌문을 선택 항목에 넣을 수 있으며, 저장은 검토 대기로 처리한다.
회사 폴더 파일은 기존 참고자료 등록·본문 확인 또는 중앙 회사자료 연결을 통해 사용한다.
노션은 확인한 페이지 주소와 발췌문을 연결하며 자동 계정 동기화는 하지 않는다.

출력은 공고에 첨부된 실제 HWPX 전체의 사본이다. 지정한 작성 칸의 텍스트를 바꾸고
원본 표·셀 병합·글꼴·이미지 등을 유지한다. 첨부 원본 자체를 덮어쓰거나 새 공통
템플릿으로 바꾸지 않는다. 본문 이외의 공고·평가표도 원본 사본에 포함된다.
HWP/PDF와 작성 칸을 구조적으로 식별하지 못한 파일은 지원 불가 사유를 표시한다.

제안요청서에서 작성일자 1개·서술 4개·일반현황 8개·선택 3개, 총 16칸을
식별한다. ‘6. 산출 공내역서.hwpx’는 제목과 단가/금액 등 고정 열 머리글이
일치하는 표의 15칸을 지원한다. 상위 1식 행 2칸, 세부 5개 품목의 단가/금액
10칸, 공급가액·부가가치세·합계 3칸이다. 숫자는 근거와 함께 입력하며 자동
가격 계산은 없다. 고정 품명·규격·단위·수량·비고는 편집하지 않는다.

회사 자격·신용·매출·실적·납세증명 원본은 확보되지 않았다. 이 값들을 예시로
만들어 증빙으로 인정하지 않는다. 주민등록번호와 서명·날인은 자동 작성 대상에서
제외한다. 노션 및 기존 작성자료의 내용은 승인된 회사 증빙으로 전환되지 않는다.

## API

- `GET /v2/notices/{notice_no}/form-fields`: 원본 파일별 지원 상태, 항목명·주변 안내·현재 작성 내용.
- `POST /v2/notices/{notice_no}/form-fillings`: 입력 버전·원본 해시·중복방지 키와 항목별 내용/인용을 검증하여 저장.
- `GET /v2/notices/{notice_no}/form-fillings/{document_id}/download`: 최신 원본과 근거를 재확인하고 원본 서식 HWPX 사본 다운로드.
- `inputs.form_fillings`: 문서별 작성값, 원본 연결, 항목별 근거, 검토 대기 상태.

원본 동기화는 기존 작성값을 보존한다. 변경된 원본/근거는 다시 확인해야 하며,
과거 위치 매핑을 새 파일에 적용하지 않는다. 저장·다운로드 성공은 적격 승인이나
제출 준비 완료를 의미하지 않는다. 서식 내용과 실제 한글 배치 검토는 별도로 남긴다.

## 검증 범위

API 테스트는 실제 ZIP/XML 구조, 잘못된 위치·원본 해시·인용, 입력 충돌, 재요청,
원본 보존과 출력값 재추출을 확인한다. UI는 항목별 저장과 출처 연결, 충돌 시
미저장 내용 보존, 지원 불가 표시와 HWPX 다운로드 연결을 확인한다.

`tools/verify_original_form_output.py`는 원문/출력 ZIP·표·셀·스타일·문단 구조를
대조한다. 이 구조 검사는 한글 편집기의 재조판·페이지 배치 검토를 대신하지 않는다.
현재 HWP Worker 복구 필요 상태는 해제하지 않으며, 별도 COM 작성기나 보안 우회는 없다.
