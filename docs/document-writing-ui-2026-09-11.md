# 문서별 비교·작성 작업대

## 후속 보완: 공고 검토에서 작성 대상으로 연결

- 아래 초기 구현의 고정 문서 3종·공통 목차·임의 서류 추가는 제거했다. 비교·작성은 확인된 `writing_plan`의 직접 작성 항목만 표시한다.
- 공고 서류 검토에서 원문 발췌로 작성/원본 첨부/전자 제출 후보를 제시하고 담당자가 포함 여부와 처리 방법을 확인한다. 자동 탐지는 완전한 추출이 아니며, 누락된 실제 서류·세부 항목은 원문 인용으로 추가한다.
- `PUT /v2/notices/{notice_no}/writing-plan`: `version`, `note`, `items[{id,title,document_kind,action,document_id,quote}]`. 실제 공고 원문과 인용 및 제목을 검증하고 감사 이력을 남긴다. 발급 증명서의 직접 작성은 거부한다.
- 응답에 `writing_plan_current`와 `inputs.writing_plan`을 추가했다. 모든 공고 원문의 내용·파일 해시를 연결하여 원문 변경 시 다시 확인하게 한다. 전체 요구사항 검토나 제출 승인을 자동 완료하지 않는다.
- 초안 저장 API는 확인된 직접 작성 항목의 ID/제목/구분만 허용한다. 원본 첨부 항목은 실제 체크리스트에 연결된다. 기존 초안·원문·실패 이력은 삭제하지 않는다.
- 현재 공고의 확인 버튼을 대신 누르지 않았다. 담당자가 검토 화면의 ‘확인 완료 · 비교·작성으로 이동’을 누르면 실제 항목이 표시된다.
- 후속 회귀: 원문 없는 항목 거부, 검토 전 저장 차단, 실제 대상만 저장, 발급 증명서 구분, 원문 변경 후 재검토, 기존 초안 보존. 브라우저 mock E2E는 검토 확인 → 정성제안서/서약서 작성 → 저장/재조회 흐름을 검증한다.
- 후속 검증 결과: 전체 백엔드 1,312 passed / 13 skipped, 프론트 전체 184 passed 및 마지막 추출 회귀 2건 통과, 타입 검사 통과, mock E2E 6 passed / 2 skipped. 현재 공고의 작성 대상 후보를 실제 브라우저에서 확인했으며 확인 완료 버튼은 누르지 않았다.

## 구현

- 비교·작성에 정성제안서 / 입찰서 / 기타서류 목록과 독립 편집기를 추가했다. 서류 추가로 서약서, 정량평가 자료, 제안요약서 등을 별도로 작성할 수 있다.
- 요구사항 채택이나 회사 참고자료 등록 없이도 작성 초안을 저장할 수 있다. 저장은 승인과 구분하며 기존 요구사항별 편집은 접힌 영역에 유지했다.
- 서류별 제목, 본문, 회사 자료 인용, 웹 참고자료를 기존 `inputs.proposal_sections`에 저장한다. 버전 검사, 동일 요청 중복 방지, 감사 이력을 적용한다. DB 마이그레이션은 없다.
- 회사 자료는 파일명/본문 검색, 본문 선택·발췌, 작성 내용 삽입을 지원한다. 현재 공고의 `company_reference`만 허용하고 원문 포함 여부를 서버에서 검사한다. 증빙 승인으로 전환하지 않는다.
- 웹검색은 Google/네이버 **새 탭 검색 링크**다. 검색 결과 API나 자동 크롤링은 추가하지 않았다. 사람이 선택한 URL·제목·발췌문을 등록하고 `[검증필요]`로 삽입한다. 서버는 http(s) 및 자격증명 없는 URL만 허용하며 웹 주소를 직접 가져오지 않는다.
- 기본 목차는 작성용 뼈대이며 공고 양식 또는 완성 문서가 아니다. 발급 증명서를 직접 작성한 것으로 취급하지 않는다.
- 저장한 서류는 각자 Markdown 텍스트 초안으로 다운로드한다. 검토 패키지에는 개별 `drafts/*.md`와 해시를 포함한다. 정성제안서·기존 섹션만 제안서 HWP 본문에 포함하고 입찰서/기타서류는 섞지 않는다. 새 문서별 HWP/PDF 양식 렌더링은 이번 변경에 포함하지 않았다.
- 회사/웹 자료를 붙여도 자동 승인하지 않는다. 미검증 웹 자료가 연결된 초안은 기존 섹션 승인 API에서도 차단한다.
- 문서·탭 이동 중 미저장 내용을 유지하며 저장 실패에도 본문을 남긴다. 서버에서 같은 문서가 바뀌면 덮어쓰지 않는다. 모바일에서는 서류 선택 메뉴를 사용한다.

## API

`POST /v2/notices/{notice_no}/document-drafts`

필수: `version`, `draft_id`, `idempotency_key`, `document_kind`, `title`, `text`, `note`.
`document_kind`: `qualitative_proposal | bid_document | other_document`.
선택: `references[{document_id,quote}]`, `web_references[{title,url,quote}]`.
응답: 기존 `WorkspaceRecord`; 저장된 섹션에 문서 구분/제목/참고자료가 추가된다.

`GET /v2/notices/{notice_no}/document-drafts/{draft_id}/download`: 인증된 Markdown 초안 다운로드.

## 검증

- `ruff check api tests`: 통과.
- 전체 `pytest -q`: 통과. 실연동 opt-in 테스트는 skip이며 Qdrant 버전 경고가 있다.
- 프론트 타입 검사: 통과.
- Vitest: 183개 통과. 기존 상태 컴포넌트의 React act 경고가 있다.
- Playwright workbench-mock: 6개 통과 / 2개 기존 skip.
- 신규 E2E: 문서 3종 저장, 전환 중 내용 유지, 회사 인용, 검색 URL, 웹 발췌문, 다운로드, 재조회, 1280/390px 가로 넘침 검사. 외부 검색 엔진 응답 자체는 검증하지 않았다.
- API 회귀: 요구사항 없는 초안 저장, 중복 요청, 오래된 버전 거부, 인용/URL 검증, 승인 차단, 문서 분리, 패키지 해시 대조.
- 기존 검증 DB 및 작업 폴더를 유지해 8002 API와 idle 실행기를 갱신했다. 운영 3000/8001과 HWP COM Worker는 변경하지 않았다.
- 현재 공고 `R26BK01722905-000`의 비교·작성 화면을 브라우저에서 확인했다. 입력 버전 3과 기존 원문/이력은 보존했고 실제 공고에 시험 초안을 저장하지 않았다.
