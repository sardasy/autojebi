# 원본 HWPX 양식의 사람 검토 경로

## 변경

기존에는 저장한 원본 양식이 하나라도 있으면 `service.blockers`가 항상 차단했고,
패키지에도 양식 검토 경고를 항상 추가했다. 작성된 HWPX 사본의 정확한 파일을
사람이 검토한 뒤 승인 또는 반려할 API와 화면을 추가했다.

비교·작성 → 공고 첨부 양식 작성 → 작성본 검토 시작 → 검토할 작성본 다운로드 →
원본/작성 내용·근거/실제 한글 배치 확인 → 의견 입력 → 승인·반려 순서다.
미작성 항목이 있거나 세 확인 중 하나라도 빠지면 승인할 수 없다.
자동 작성에서 제외된 서명·날인 등의 완결성도 담당자가 실제 문서에서 확인해야 한다.
수정한 로컬 파일을 다시 업로드해 승인하는 기능은 이번 범위에 포함하지 않는다.

## 계약과 무효화

- `GET .../form-fillings/{document_id}/review`: 현재 입력 버전, 출력 SHA-256,
  미작성 수, 해당 출력의 검토 상태. 읽기 전용으로 저장값을 재검증한다.
- `POST .../form-fillings/{document_id}/review`: `version`, `output_sha256`,
  `approved`, `source_checked`, `content_checked`, `layout_checked`, `note`.
- 검토용 다운로드는 `version`과 `output_sha256` 쿼리를 확인한다.
  화면 확인 이후 다른 입력/파일로 바뀌면 다운로드와 승인 요청을 거절한다.
- 승인은 검토 당시의 입력 내용 및 출력 바이트 해시와 연결한다. DB의 입력·작성
  내용 변경은 검토 상태를 대기로 되돌리며, 디스크의 원본/근거 변경은 조회와
  최종 준비 검사에서 차단한다. 원본/근거 파일과 작성 위치도 승인 시 재검증한다.
- 입력 버전은 검토 기록에서도 증가한다. 내용이 같고 원문 확인 여부 또는 섹션/
  양식 검토만 바뀐 경우 양식의 내용 검토를 유지한다. 본문 섹션 승인은 양식 승인
  때문에 초기화하지 않는다. 기존 생성물과 패키지의 버전 검사는 그대로 유지한다.
- `inputs.form_fillings[].review`에 입력 버전, 의견, 확인 항목, 검토 시각,
  입력 내용 해시, 출력 해시를 보관한다. 기존 감사 이력에는 이전 입력을 보존한다.
  공유 API 키 기반이므로 개인별 승인자 인증·RBAC가 구현됐다는 의미는 아니다.
- 유효한 승인과 빈칸 없는 작성본만 양식 차단 및 패키지 양식 경고를 해제한다.
  원본/출력 바이트는 승인 전후 동일하며, 파일 내부의 검토용 안내 및 파일명은
  유지한다. 별도 검토 기록과 manifest가 동일 파일에 대한 검토 완료를 나타낸다.
- `company_reference`는 계속 참고자료이고 증빙으로 승인·재분류하지 않는다.
  마감, 필수 증빙, 요구사항, 본문 및 생성물/최종 패키지 검토는 별도로 필요하다.

## 검증

- 전체 백엔드 `pytest -q` 통과. 이후 추가한 패키지 통합 테스트 3건도 통과.
- 통합 테스트는 합성 원본 HWPX 및 합성 증빙/생성물을 사용한다. 양식 승인과
  다른 필수 검토 완료 후 실제 `run_package`와 최종 검토 API를 통해 `ready=true`,
  원본 파일 변경 후 `ready=false`를 확인했다. 과거 패키지는 보존된다.
- 양식 버전 충돌, 다른 출력 해시, 누락 확인, 공백 의견, 미작성, 반려,
  회사/근거/작성값/매핑/디스크 변경, 재요청 충돌을 회귀로 확인했다.
- 프론트 전체 36개 파일 / 243개 테스트 통과. 타입 검사 및 lint 통과.
- Playwright `workbench-mock`의 `document-writing-mock.spec.ts` 2건 통과.
  신규 검토 흐름의 해시를 지정한 다운로드·명시적 승인·수정 후 재검토와 기존
  문서 작성 흐름을 확인했다. 외부 API는 모의 응답을 사용했다.
- 변경 Python 파일 Ruff 및 `git diff --check` 통과. 전체 Ruff는 기존 테스트
  7개 파일의 I001 import 정렬 오류로 실패했다. 이 작업에서 해당 파일은 변경하지 않았다.

## 아직 검증하지 않은 범위

이번 변경은 소스 코드와 격리된 테스트의 결과다. 운영 API/실행기/컨테이너를
재배포하지 않았으며 실제 공고를 승인하거나 HWP Worker를 복구하지 않았다.
실제 한글에서 CRLF 수정 후 생성/배치 대조, 실공고 3~5건과 담당자 최종본 비교,
첨부 추출 범위 확대, 개인 인증/역할 분리는 여전히 남아 있다.
