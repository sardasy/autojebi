# 실무용 v2 구현 및 전환 기록

2026-09-06 작성, 2026-09-07 보완. **검증 환경용 구현이며 운영 전환 승인이 아니다.** 실제 HWP 및 실무 공고 3건 대조 기준은 아직 충족하지 못했다. 최신 증거는 [보완 진행 기록](remediation-progress-2026-09-07.md)과 [실제 공고 리허설](real-rehearsal-2026-09-07.md)을 따른다.

## 구조와 안전 규칙

- `/workspace`는 기존 화면과 병행하는 새 작업대이며 기본 `/notices`는 유지한다. `WORKSPACE_V2_ENABLED=true`일 때 메뉴를 노출한다.
- `notice_workspaces`는 사람의 참가 결정·입력 버전·검토 입력을 보존한다. `workspace_jobs`는 실행 상태와 입력 스냅샷·결과·오류를 보존한다. `workspace_reviews`는 변경 전 입력과 검토 기록을 추가 방식으로 저장한다. `workspace_llm_budgets`는 공고별 동일 원문·회사·증빙 내용에 대해 분석·제안서 합계 최대 2회 유료 호출을 제한한다. 결정·검토·분석 반영으로 버전이 증가해도 한도는 복구되지 않는다. 실제 내용 변경은 별도 예산이며 공고 생애 전체의 절대 2회 제한을 뜻하지 않는다. 실패·응답 불명 호출도 차감하며 과거 카운터는 삭제·초기화하지 않는다. 입력을 확정할 수 없는 과거 사용량은 보수적으로 모든 내용의 예산에 포함한다. 완료 결과는 작업별 정확한 입력·프롬프트·모델·인용 연결이 일치하고 인용이 유효할 때만 재사용한다. 채택·승인 상태만으로 생성·재실행·캐시 재사용을 차단하지 않는다. 실행 결과는 해당 작업에만 저장하며 기존 입력·정상 결과·검토 이력을 보존한다. 작업 결과의 입력 반영은 별도의 사람 검토 단계다.
- `POST`는 실행 요청을 먼저 커밋하고 202/작업번호를 반환한다. 별도 Worker가 PostgreSQL 행 잠금과 CAS로 작업을 인수한다. 세션 advisory lock은 처리 전체를 감싸므로 같은 DB에 연결된 v2 Worker끼리는 순차 실행한다.
- 실행 중 입력/회사/템플릿/원본 메타가 바뀌면 결과를 차단한다. 과거 정상 결과와 파일은 삭제하지 않는다. 20분 임대 만료 작업은 실패 이력으로 남기며 자동 재시작하지 않는다. HWP 재요청은 파일과 실제 Worker 상태를 먼저 확인해야 한다.
- 동일 요청 키는 같은 작업을 반환한다. 실행 중/완료 작업은 같은 버전에서 재사용한다. 검토 패키지는 승인 이력이 바뀔 수 있으므로 새 요청 키로 재생성할 수 있다.
- 공고 원문은 회사 증빙으로 변경할 수 없다. 업로드 분류/연결만으로 준비완료가 되지 않는다. 본문 또는 근거 변경은 관련 검토와 제안서 승인을 무효화한다.
- 원문 전체 확인과 요구사항 등록, 필수 증빙, 제안서 사실 확인을 완료해야 제출 준비 검사를 통과한다. 경고 초안 승인은 제출 준비 완료와 다르다.
- 패키지에는 원본, Excel/HWP, 제안서 텍스트, 입력·검토 manifest, 누락 목록을 담는다. 원본/생성물 해시를 검증하고 입력 버전이 바뀌면 과거 승인으로 새 파일을 승인하지 못한다.
- 실제 투찰·금액 입력·제출과 외부 알림 실전송은 v2에서 제공하지 않는다.

## 호환 경로에서 수정한 문제

- LLM 인증/응답 오류는 502와 별도 오류 이력으로 처리한다. 점수·문서·기존 상태는 보존한다. 정상 재분석은 문서 데이터를 병합 보존한다.
- 공고 PDF를 사업자등록증으로 자동 연결하지 않는다. 일반 업로드도 자동 준비완료 승격을 제거했다. 재분석 시 수동 막힘 상태를 보존한다.
- 파일 저장 문구·Worker 메타 JSON·추출 오류를 본문이나 실제 요구값으로 사용하지 않는다.
- 수동 Upsert와 수집 경로에 공통 정규화 함수를 적용했다. 추정가격/배정예산을 기초금액으로 대체하지 않는다.
- 서류 분석/규격 추출/HWP 단계 이후 그레이딩을 허용하고 오류 분석을 거부한다. 알림은 상태를 전환하지 않고 로그만 추가한다. 그레이드 실알림 기본값은 false다.
- 기존 동기 API를 모두 v2 큐로 전환한 것은 아니다. 새 화면의 요청만 v2 API/큐를 사용한다. 기존 Proposal API의 교체와 운영 기본 화면 전환은 별도 검증 후 진행한다.

## v2 인터페이스

모든 `/v2/*` API에 기존 X-API-Key 인증을 적용한다. Next의 `/api/v2/*`는 키를 서버에서만 주입하고 변경 요청의 Origin을 설정된 화면 출처로 제한한다. 하나의 운영자 환경이며 개인 계정별 신원 증명은 제공하지 않는다.

| 경로 | 동작 |
|---|---|
| `GET/POST /v2/notices` | 목록/수동·검색 결과 등록. 기존 공고 등록은 덮어쓰지 않음 |
| `POST /v2/search` | 기존 G2B 검색 공통 서비스 사용 |
| `POST /v2/notices/{no}/initialize` | 기존 원본을 보존하고 새 작업대 시작. 과거 승인/점수 승계 안 함 |
| `GET /v2/notices/{no}/workspace` | 결정·버전·누락·작업·검토 통합 조회 |
| `POST .../sync`, `.../decision` | 원본 동기화/사람 참가 결정. 버전 충돌은 409 |
| `POST .../jobs` | `fetch/analyze/grade/extract/proposal/verify/excel/hwp/package/notify` 작업 요청 |
| `GET /v2/jobs/{id}`, `.../download` | 실행 결과/해시 검증 다운로드 |
| `POST .../jobs/{id}/apply` | 추출 본문·요구사항·초안을 담당자가 새 입력 버전으로 반영 |
| `POST .../documents` | 역할을 지정한 파일 등록 |
| `POST .../documents/{id}/text`, `.../review` | 확인된 본문 등록/증빙 확인·반려 |
| `POST .../documents/{id}/source-link` | `{version, attachment_index, note}`로 공고 원문/변환본을 공식 첨부 슬롯에 연결. 사람 승인과 별개 |
| `POST .../requirements`, `.../source-review` | 인용 검증 요구사항 편집/전체 원문 대조 확인 |
| `POST .../commercial` | 확인된 견적 증빙과 원화 총액·수량 등록. 입력 버전/근거 검사 |
| `POST .../sections/{id}/review` | 제안서 본문 수정 및 사실 확인 |
| `GET .../hwp-context`, `POST .../reviews` | HWP 입력 미리보기/초안 승인·반려·제출 준비 검사 |
| `GET /v2/settings` | 키 등록 여부와 최근 LLM/HWP 실행 결과. 등록됨은 연결 성공이 아님 |
| `GET /v2/worker/health`, `POST /v2/jobs/{id}/recover` | 실행기 상태/담당자 확인 후 새 복구 작업 요청. HWP 자동 재호출 금지 |

오류는 `detail.code/message/next_action/job_id`를 사용한다. 작업 오류는 작업번호와 함께 조회 가능하다. Provider 원문 예외는 시크릿 유출 위험 때문에 저장하지 않는다.

### 공식 첨부와 원본 보존

작업대 조회에는 `source_attachments`가 포함된다. 선언된 첨부마다 `index/name/url/document_ids/state`를 반환하며 `missing/unread/ready`는 각각 파일 미확보/본문 미확인/본문 확보다. 본문 확보가 담당자 승인이나 제출 준비 완료를 뜻하지 않는다.
지원하지 않는 확장자나 주소 없는 첨부도 목록에서 제외하지 않는다. 첨부 작업의 `source_inventory`에 슬롯별 다운로드/중복/실패/미지원 결과를 남긴다. 전체 다운로드 실패는 실패 작업, 부분 실패는 경고 작업이다.
XLS/ZIP은 기본 허용 형식에 포함해 원본 바이트를 보존하되 자동 실행·압축 해제·본문 추출은 하지 않는다. 한글 Worker에는 문서명과 보관 경로가 모두 HWP인 파일만 전달하며, HWPX도 두 확장자가 일치해야 본문 추출한다.
원문 미확보/미확인 상태는 과거 `source_reviewed` 또는 패키지 준비 이력으로 우회할 수 없다. 사람이 확인한 변환본은 `source-link`로 명시 연결할 수 있으며 관련 승인은 재검토 상태가 된다.
동일 요청 키의 과거 작업은 보존한다. 과거 첨부 결과가 선언된 전체 목록을 포함하지 않았을 때는 새 요청 키로 재수집할 수 있다. 실행 중 작업이나 아직 반영하지 않은 완전한 첨부 결과는 재사용한다.

## 실행과 전환

검증 DB는 `autojebi_workspace_v2_check`, 동시성 시험 DB는 `autojebi_workspace_queue_check`를 새로 만들었다. 기존 운영 `3000/8001`, 기존 데모 DB는 마이그레이션/데이터 변경하지 않았다.

```powershell
$env:DATABASE_URL = '<검증용 PostgreSQL 연결 문자열>'
python -m alembic upgrade head
python -m api.hwp_fields seed
./infra/start-workspace.ps1 -DatabaseUrl $env:DATABASE_URL -Python '<Python 3.11+ 실행 파일>'
```

화면은 `http://127.0.0.1:3002/workspace`, API는 8002다. 시작 스크립트는 점유 포트가 있으면 중단하며 기존 프로그램을 종료하지 않는다. API/큐/프론트는 숨김 프로세스로 실행한다. DB 마이그레이션은 시작 스크립트가 자동 수행하지 않는다.

- 업로드/생성물/로그: `data/workspace/`, Git 제외. Next 빌드 경로는 `.next-workspace`로 분리한다.
- `API_KEY`/`INTERNAL_API_KEY`는 동일한 실제 값으로 설정하되 저장소에 기록하지 않는다. 검증 환경의 인증 공란 우회는 운영용이 아니다.
- HWP 템플릿 루트는 `data`, seed 경로는 `templates/...hwp`이므로 실제 파일은 `data/templates`에 둔다. 필드는 운영자가 한글에서 삽입해야 한다.
- 2026-09-07 보완: Worker는 `api/hwp_worker`에 구현했다. 토큰 32자 이상 필수, 생성 요청은 자동 재시도하지 않는다. 전용 스레드와 Windows 전역 mutex, 저장 후 재조회 검증을 제공한다. 모의 검증과 실제 COM/문서 배치 검증은 구분한다. [운영 안내](hwp-worker.md).
- 제안서 전체 본문을 HWP에 넣으려면 `proposal.body` 매핑을 추가하고 실제 해당 필드를 삽입한다. 기존 seed의 요약 전용 매핑만 있으면 경고를 남기고 최종 패키지를 완료로 승인하지 못한다.
- 전환 전 DB 및 업로드/생성물 폴더 백업, 파일 해시 목록 확보, 복원 리허설을 수행한다. 추가 마이그레이션은 `0013_workspace_jobs`, `0014_workspace_llm_inputs`다. downgrade는 신규 v2 이력/예산을 제거할 수 있으므로 운영 데이터가 생긴 후 무작정 실행하면 안 된다. [검증 DB·파일 복원 결과](workspace-backup-restore-2026-09-07.md)를 운영 전체 백업으로 간주하지 않는다.

## 초기 검증 기록 (2026-09-06)

- 신규 PostgreSQL에서 초기 revision부터 `0013_workspace_jobs`까지 upgrade 성공.
- 실제 PostgreSQL에서 Worker 2개 접근 시 순차 처리 회귀 테스트 통과.
- 프론트 타입 검사 통과. Vitest 120건 통과.
- v2 브라우저 E2E 1건 통과: 참가 결정 저장 → 실제 큐 Excel 생성 → 다운로드 → dry-run 상태 유지 → HWP 필수값 차단 → 새로고침 유지.
- 1280px/390px 스크린샷을 확인했고 모바일 페이지 전체 가로 넘침 검사를 통과했다. 원문·근거 편집과 실제 긴 HWP 출력의 시각 검증을 대체하지 않는다.
- HWP mock은 실제 문서가 아닌 테스트 바이트를 반환하며 PutFieldText payload/해시/잔여 필드 보존만 검증한다. 실제 HWP 성공으로 세지 않는다.
- 전체 백엔드: 456 passed / 1 skipped. 기본 skip인 PostgreSQL 전용 테스트는 별도 환경변수를 지정해 1 passed를 확인했다. Ruff, 프론트 lint/typecheck도 통과했다.
- 실제 HILS 공고는 검증 DB에 원본 4개를 등록했다. 기관/마감이 정상 표시되고 참가 결정은 미결정이다. 실제 PDF 본문 추출을 수행했으며 한글 원본 3개는 Worker/인증 미설정으로 경고가 남았다. 회사 증빙으로 자동 연결하지 않았다.

## 출시 전 미완료

1. 실제 LLM 인증, Windows/HWP Worker 연결, 회사 증빙과 템플릿 필드 준비 후 실파일 확인.
2. HILS·소프트웨어·물품 실제 공고 3건의 담당자 정답표 대조 및 필수 요구 누락 점검. 현재 테스트용 합성 공고는 이 기준에 포함하지 않는다.
3. v2 그레이딩에 근거·충족 판정·SKU 참고·자격 조회·확인된 견적 가격 비교를 연결했다. 미평가는 점수 없이 남기며 실제 회사/제품 자료와 담당자 판정으로 결과를 검증해야 한다. Qdrant 후보 유사도를 기술 적합 판정으로 사용하지 않는다.
4. 사람의 인용·수치·사실 확인은 필수다. 자동 검사는 의미적 참/거짓을 보증하지 않는다. 날짜/자격처럼 회사 증빙 외의 확인 방식이 필요한 요구사항의 검토 UX는 추가 리허설 대상이다.
5. 실제 G2B 검색 및 SW/물품 원문 다운로드 성공은 기록했다. HWP 성공/경고 승인, 전체 패키지 무경고 완료, 운영 백업 복원 및 기존 API 완전 전환은 아직 출시 승인 근거가 없다.

위 항목이 해결되기 전에는 v2를 운영 완료로 표시하거나 기존 기본 화면을 교체하지 않는다.
