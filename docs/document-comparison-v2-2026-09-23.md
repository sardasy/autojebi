# HWPX 본문 규칙 v2 · 문서 비교 v2 구현 기록

## 범위와 착수 전 확인

같은 원본 파일의 저장 본문과 별도 기준 추출을 비교한다. 주 추출기 교체, RAG 자동 채택, 서로 다른 공고 파일 비교는 포함하지 않는다. DB 마이그레이션은 없다.

| 확인 항목 | 확인 결과 및 결정 |
|---|---|
| 기준 표 ID | 설치된 kordoc 4.14.1의 HWPX 표 `source_id`는 XML 표 `id`다. 어댑터 밖에서는 `reference_table_id`만 사용한다. 양쪽에서 유일한 ID만 연결한다. |
| v1 본문 인정 범위 | `Contents/section*.xml`의 모든 요소 text/tail 문자 노드다. 속성과 다른 XML 파일은 제외한다. 섹션 안 머리말·꼬리말, 각주·미주, 글상자, 캡션, 숨은 설명, 수식 스크립트, 하이퍼링크, 변경 추적 삭제 텍스트, 중첩 표는 문자 노드인 경우 모두 포함한다. 이 포함 규칙을 유한한 태그 목록으로 축소하지 않았다. |
| 필드 파라미터 | `http://www.hancom.co.kr/hwpml/2011/paragraph` 네임스페이스의 `fieldBegin/parameters` 서브트리만 제외한다. 파라미터 밖 표시값과 tail, 일반 본문의 Clickhere·숫자는 보존한다. |
| 저장 오프셋 | Python 유니코드 코드포인트. `offset_unit=unicode_codepoint`. 유니코드 정규화 없음. |
| HWP 명령 누수 | 시험 HWP의 기존 COM 본문에서는 발견되지 않았다. 전체 HWP에 대한 보장은 하지 않으며 의심 변경은 분류 미확인으로 표시한다. HWP 추출 규칙 자체는 변경하지 않았다. |
| 제어문 집계 | 시험 HWPX의 텍스트가 있는 parameters 서브트리 23개를 재확인했다. 토큰 230개가 아니라 제어문 23묶음이다. |

ADR-1/2/3/5/6을 적용했다. **ADR-4는 A: 기존 재검토 정책**이다. 실제 본문 변경의 연결 요구사항·섹션만 기존 provenance 규칙대로 재검토하며 과거 감사 이력을 보존한다. 반려 상태 보존 등 기존 정책도 유지한다. 인용 재매핑을 통한 승인 유지는 구현하지 않았다.

## 구현 경계

- `api/parsing/hwpx_text.py`: 버전별 순수 본문 추출. 한 번의 섹션 순회에서 문자열·문단/행/셀 범위·필드 제외 기록·중첩 표를 함께 생성한다. v1은 이전 itertext 문자열과 순서를 재현한다. v2도 필드 파라미터 외의 문자를 추가로 제외하지 않는다.
- `attachment_text.extract_hwpx`: 다중 섹션과 ZIP 공통 경로, 본문 해시·위치 메타데이터·규칙 버전 기록. 기존 규격 검색용 표 검증은 독립적으로 유지하므로 중첩 표 승인 제한은 완화되지 않는다.
- `api/services/document_reference.py`: 기준 추출기를 호출해 중립 본문·표·셀·정확한 범위로 변환한다. 전체 본문을 조각으로 정확히 재구성할 수 없거나 중첩 셀 위치가 유일하지 않으면 위치를 확정하지 않는다.
- `api/parsing/document_comparison.py`, `text_diff.py`, `table_diff.py`: XML 파싱과 kordoc 직접 import 없이 순수 비교를 수행한다. E1/E2 재구성은 추출 API를 호출한다.
- `api/workspace/document_jobs.py`: 작업대 행 잠금 안에서 규칙·원본/저장 본문 해시·입력 버전 등을 포함한 작업 식별을 계산한다. 예전 식별자가 없는 작업은 새 작업으로 실행하며 이전 이력은 보존한다.
- 추출 실행기와 apply: 수동 확정 본문을 보호한다. v1 HWPX는 수동 추출 요청 때 재추출하고 정상 v2는 재사용한다. 실행은 입력을 바꾸지 않으며 반영에서만 버전과 연결 검토를 처리한다. 메타데이터만 바뀌면 본문 변경으로 취급하지 않는다.
- 화면: `ComparisonDetails`가 구간/셀을 표시한다. `textOffsets.ts`의 공통 코드포인트 유틸을 통해 이모지 이후 범위도 정확히 강조한다. 양쪽 모두 주변 문맥을 제공한다.

## 결과 계약과 비교 규칙

기존 `POST /v2/notices/{notice_no}/jobs`, `kind=document_compare`를 유지한다. `comparisons[]`의 새 항목은 `reference`와 `comparison_v2`다. 기존 결과의 `candidate`/`comparison`은 변환하지 않고 “이전 비교 방식”으로 보여준다.

`comparison_v2`는 Pydantic 계약으로 검증한다:

- `comparison_version=2`, `offset_unit=unicode_codepoint`, `offset_basis=comparison_text`.
- `completion=complete|truncated`, `truncation_reason`.
- `basis=stored|legacy_extraction|current_extraction`, `has_baseline`, `verified=false`.
- `before_text`, `after_text`, `changes`, `controls`, `tables`, `summary`.
- summary는 본문 변경/공백 구간, 분류 미확인 건, 제어문 묶음, 변경 셀, 구조 변경 표, 대응 미확인 표, HWP 셀 미비교를 구분한다.

구간 오프셋은 **반환된 comparison_text**에 대한 값이다. E1 저장 본문이면 제어문은 원본 E1 위치로 별도 반환하고, 본문 쪽은 E2를 사용한다. 양쪽 정확한 범위가 확인된 표의 셀 텍스트는 비교 문자열에서 제외한다. 따라서 비교 구간을 저장 본문 인용 위치로 사용하면 안 된다. 표 좌표는 XML cellAddr/cellSpan을 보존하며 새로 추정하지 않는다.

문단→어절→문자 비교에 `SequenceMatcher(autojunk=False)`를 사용한다. 숫자 부호·소수점·천 단위 구분은 원자 토큰으로 유지하고 문장 이동은 삭제·추가로 표시한다. 공백 집합은 탭/LF/CR/U+0020/U+00A0/U+2000~200A/U+2028/2029/U+202F/U+205F/U+3000으로 고정했다. 다른 문자가 섞인 변경은 본문 변경이다.

표는 ID 유일성·격자·병합·본문 위치를 모두 확인한다. 구조 변경이면 셀 대조를 중단하고 행 비교를 제공한다. 대응이 불확실하면 표 텍스트를 본문 비교에 남긴다. 중첩 표 범위는 합집합으로 제거하고 자식 표의 텍스트는 부모 셀 집계에서 제외한다.

전체 완료·본문 변경 0·미확인 0일 때만 “본문 내용 차이 없음”을 표시한다. 변경 셀/표 구조/대응 미확인/HWP 셀 미비교를 첫 줄에 함께 표시한다. 저장 본문이 없으면 “기존 본문 없음”이며 차이 없음 판정이 아니다.

## 제한과 측정

기존 파일 50MB, 추출 본문 200,000자, ZIP 확장/깊이, Node 30초·출력 4MB, 공고당 비교 10문서·총 결과 8MB 제한을 확대하지 않았다. 추가 상세 비교는 5초/연산량 2,000,000/텍스트 비교당 500구간, 문서 상세 1MB로 제한한다. 범위를 넘으면 `truncated`와 이유를 반환한다. 제한 때문에 제거한 상세를 “차이 없음”으로 표시하지 않는다. 파서 시간 초과·읽기 실패는 실패 항목으로 보존한다.

로컬 실제 공고 폴더의 HWP/HWPX 39개 중 최대 파일은 `R26BK01712477-000`의 HWP **392,704바이트**였다.

- 기준 추출 14,106자, 직렬화 결과 **258,776바이트**(v2 상세 61,993바이트), 상세 잘림 없음, 0.453초(기준 추출+비교), 원본 SHA 불변.
- **측정 한계:** 현재 시험 DB에는 해당 실제 공고의 저장 본문이 없다. 기존 인증 Worker의 읽기 전용 본문 추출도 `com_call_failed`로 실패했다. 따라서 위 크기는 저장 본문 없는 결과의 크기이며 두 본문을 갖춘 최대 실공고 비교 측정은 아직 충족하지 못했다. 이를 전체 대조 성공이나 정확도 검증으로 보고하지 않는다. 한도는 확대하지 않았다.
- 측정 기록: `data/workspace/kordoc-validation/comparison-v2-largest.json` (gitignore).

## 검증 결과

백엔드 전체 pytest, 프론트 전체 Vitest(43파일/294테스트), ruff, import-linter(3계약), ESLint, TypeScript, Next.js 프로덕션 빌드를 통과했다. 환경 게이트가 있는 라이브 테스트는 기존 정책대로 skip한다. 최종 변경의 비교/fitness/architecture 집중 회귀도 별도 실행했다.

회귀에는 필드 표시값·URL·fieldEnd 부재·다중 run/문단·tail·네임스페이스·전체 기존 문자 노드 범주·다중 섹션·중첩 ZIP/표·빈 셀·이모지 위치·숫자/단위/부정 표현/순서·E1/E2/수정 본문·중복 ID/구조 변경·표 이중 집계·잘림·HWP 미확인·수동 확정 보호·규칙별 작업 재사용·재검토를 포함했다.

CI fitness:

1. 포함된 원 노드와 구분자를 조합한 문자열이 실제 문단/행 범위와 일치하며 본문 해시가 일치하는지 검사한다.
2. `tests/fixtures/document_rule_hashes.json`의 버전→고정 샘플 결과 해시를 검사한다. CI는 기준 커밋과 비교해 기존 버전 해시 삭제/수정을 거부한다. 새 버전의 항목을 추가해야 한다.
3. 잘림·미확인·본문 변경이 있으면 “본문 내용 차이 없음”이 나오지 않는지 프론트에서 검사한다.
4. 비교/추출/화면의 의존 방향을 AST 검사와 import-linter로 검사한다.
5. 추출·비교만 실행할 때 입력/검토 불변, 반영 후 연결 검토와 과거 이력, 중복 반영 시 단일 버전을 검사한다.

### 실행 프로그램 검증

API 8002, 화면 3002, PostgreSQL, split local/external 실행기를 사용했다. UI 자동화는 실제 브라우저로 확인했다. 실제 공고/승인은 수정하지 않았으며 두 합성 검증 공고만 사용했다.

`E2E-KORDOC-LIVE-20260923-01`:

1. 기존 입력 v4의 토큰 비교 결과를 보존했다. 화면에서 “이전 비교 방식”과 230토큰 표시를 확인했다.
2. 합성 HWPX 문서 확인을 시험용으로 명시 저장한 v5에서 비교 v2를 실행했다. **본문 0구간 / 제어문 23묶음 / 공백 15구간 / 미확인 0 / 변경 셀 0 / 대응 미확인 0**을 화면에서 확인했다.
3. 동시에 두 건 접수한 비교와 추출이 각각 하나의 작업으로 합쳐졌다. 비교 전후 원본 해시·입력 전체·검토 기록 불변을 확인했다.
4. 화면의 “추출한 본문 반영”을 눌러 입력 v6을 만들었다. 시험용 문서 확인 상태는 미확인으로 돌아갔고 과거 검토/작업은 보존됐다. 같은 결과를 다시 반영하면 409이며 추가 버전은 생기지 않았다.
5. v6 새 비교에서 **본문 0구간 / 제어문 0묶음 / 공백 15구간 / 변경 셀 0**을 확인했다.
6. HWP는 본문 차이 없음과 함께 “표 셀 미비교 / 기존 셀 정보 없음”을 표시했다.

`E2E-COMPARISON-V2-EMOJI-20260923`:

- 합성 원본의 `😀 220 이상`과 수동 저장 본문 `😀 200 이하`를 같은 파일 비교로 시험했다.
- 실제 화면에서 `200→220`, `하→상` 두 변경 구간의 색상과 `[-]/[+]` 문자 표식을 확인했다. 이모지 뒤 오프셋이 어긋나지 않았다.
- 수동 저장 본문의 표 위치는 확정하지 않아 “표 1개 구조 대응 확인 필요”를 표시했다.
