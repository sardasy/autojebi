# 공고 서류 작성 루프

## 적용 범위

검증 환경 `3002/8002`, `WORKSPACE_V2_ENABLED=true`에서 기본 동선을 아래 네 단계로 축소했다.
운영 `3000/8001`, 기존 DB 자료와 검토 이력, 호환 API는 삭제하거나 전환하지 않았다.

1. **공고 찾기**: 나라장터 검색, 공고 저장, 작성 중 서류 선택, 수동 등록.
2. **공고 서류 검토**: 원문 확보·본문 확인, 요구사항과 인용 등록, 회사·제품 증빙 확인.
3. **비교·작성**: 회사 기존 작성자료 등록, 공고 요구사항과 나란히 비교, 참고 문장과 새 초안 저장.
4. **서류 확인**: 초안 사실 확인, 누락 검사, Excel/HWP/패키지 생성 및 검토.

상단 메뉴의 참가 결정·그레이딩·SKU·알림 진입을 제거했다. 설정에는 연결·회사정보·HWP 매핑을 남겼다.
루트와 `/notices`는 검증 환경에서 `/workspace`로 연결된다. 상세 단계는 URL 앵커로 새로고침 후 유지된다.
작업 결과는 해당 단계의 종류만 표시하며 변경·검토 이력은 접어 둔다.

## 자료와 안전장치

- 기존 작성자료는 `inputs.documents[].role=company_reference`로 구분한다. 현재는 공고별 파일 등록 방식이다.
- `POST /v2/notices/{notice_no}/reference-drafts` 요청: `version`, `requirement_id`, `document_id`, `quote`, `text`, `note`.
- 현재 공고의 요구사항·참고자료만 허용하며, 인용은 저장된 자료 본문과 일치해야 한다.
- 초안에는 참고 문장·자료 ID·자료명·입력 버전을 남긴다. 새 입력 버전을 만들고 과거 결과와 승인은 이력으로 보존한다.
- 저장 상태는 검토 대기이며 근거 목록은 비어 있다. 이전 작성자료를 증빙으로 전환하거나 단독 근거로 승인할 수 없다.
- 유료 LLM 호출 없이 사람이 비교하여 작성할 수 있다. 자동 유사문서 검색·자동 재작성·회사 공용 자료함은 이번 변경에 포함되지 않는다.
- 실제 G2B 제출과 알림 자동 실행은 추가하지 않았다.

E2E는 합성 공고와 PDF로 파일 등록, 확인된 본문 등록, 비교 작성, 새로고침 후 초안·출처 유지,
Excel 다운로드, 실패 HWP 표시, 검토 충돌, 반려 후 재생성을 확인했다.
HWP 실제 생성 성공이나 새 G2B 실검색 성공을 이번 변경의 검증 결과로 주장하지 않는다.
현재 실제 공고 `R26BK01708014-000`의 원문과 기존 기록은 보존되었으며 회사 기존 작성자료는 아직 등록되지 않았다.

재현: `frontend`에서 E2E_BASE_URL=3002 주소, E2E_API_BASE=8002 주소,
E2E_WORKSPACE_V2=true를 설정하고 `npm run e2e -- --project=workspace-v2`를 실행한다.
이미지 결과는 `frontend/test-results/writing-desktop.png`, `writing-mobile.png`에 있다.
