# 예시 파일 기반 서류 작성 E2E 결과

## 결론

2026-09-07, 검증 환경 `3002/8002`에서 예시 PDF 3개로 실제 브라우저 버튼과 영속 작업 큐를 사용했다.
**PDF 등록·추출 → 요구사항 3개 대조 → 비교 초안 3개 작성 → 근거 확인·초안 검토 → Excel/ZIP 다운로드**는 확인했다.
HWP는 필수값 누락으로 차단되어 실파일 생성 성공을 검증하지 못했다. 전체 실연동 완료나 출시 통과 판정이 아니다.

최종 공고: `E2E-SAMPLES-1788792343320`, 입력 버전 22.
실제 공고 `R26BK01708014-000`의 자료·판정은 변경하지 않았다.

## 예시 자료

모든 PDF 첫머리에 `TEST ONLY / 가상 예시 / 실제 입찰 사용 금지`를 표시했다.
각 1페이지이며 생성 후 렌더링·한글 본문 추출을 확인했다.

| 파일 (`output/pdf/document-loop-samples/`) | 내용 |
|---|---|
| `01-sample-notice.pdf` | 장비 3대, 30일 납품, 24개월 보증 요구 |
| `02-previous-proposal.pdf` | 과거 2대, 60일 납품, 12개월 보증 문장 |
| `03-sample-product-evidence.pdf` | 3대·30일·24개월을 가정한 테스트 전용 근거 |

실제 회사 정보, 제조사 확인, 실제 실적을 주장하지 않는다. 테스트의 승인도 이 합성 공고 안에서만 수행했다.

## 실제 실행

| 단계 | 확인 결과 |
|---|---|
| 공고 탐색 | 예시 공고를 수동 등록하고 저장 공고 검색으로 상세 진입 |
| 원문 등록 | 공고 PDF와 제품 근거 PDF 업로드 성공 |
| 본문 추출 | 실제 큐에서 PDF 3개를 추출, 직접 붙여 넣는 우회 없이 인용문 일치 확인 |
| 요구사항 검토 | 수량·납기·보증 요구를 원문 인용, 위치, 제안값, 가상 근거에 연결 |
| 비교 작성 | 이전 조건을 새 공고 조건으로 수정한 초안 3개 저장, 참고 문장·자료 연결 유지 |
| 부정 검증 | `[검증필요]`와 근거 없는 섹션의 승인 요청 차단 |
| 재검토 후 정상 경로 | 가상 증빙을 재확인한 뒤 요구사항 3개와 초안 3개 승인 상태 저장 |
| 누락 검사 | 완료, 최종 제출 준비 상태와 별도 표시 |
| Excel | 실제 다운로드, 요구사항 3행의 인용·제안값·근거·검토 상태 대조 일치 |
| 검토 패키지 | 실제 ZIP 다운로드, 원본 PDF 3개 해시 일치, 초안 3개 본문 일치 |
| 반려 기록 | Excel 반려 후 패키지에 반려 기록 및 검토 필요 경고 포함 확인 |
| HWP | `blocked / required_missing`: 사업자번호·대표자·주소·기관 누락. Worker 실호출 전 차단 |
| 화면 | 새로고침 후 초안·검토 상태 유지, 390px에서 페이지 가로 넘침 없음 |

외부 나라장터 실검색, 유료 LLM 분석, 실제 HWP 렌더링, 실제 제출은 이번 실행에서 검증하지 않았다.
요구사항은 사람이 원문을 대조하는 화면으로 등록했다. 자동 분석 성공으로 해석하면 안 된다.
최종 `ready=false`이며 제출 준비 확인 버튼은 실행하지 않았다.

## 발견한 보완점

1. **재추출 범위가 너무 넓음:** 이전 제안서만 새로 등록한 뒤 본문 추출을 실행해도 기존 제품 근거의 확인이 해제되고, 이미 대조한 요구사항 3개가 검토 대기·미판정으로 돌아갔다.
   `api/routers/workspace.py`의 결과 반영에서 추출 대상 전체에 `confirmed=False`를 적용한다.
   이번에는 재확인 절차로 복구했다. 후속 보완은 미추출·변경 파일만 처리하고, 본문·해시가 같은 기존 자료의 확인을 보존하는 방식이 적절하다.
2. **승인 상태와 체크박스 표시 혼동:** 최종 화면의 섹션 상태는 승인인데 ‘원문과 사실 확인 완료’ 체크박스는 체크되지 않은 상태로 나타난다.
   현재 체크박스는 새 저장 요청의 의사표시로 동작하지만 설명 없이 기존 상태와 함께 노출되어 혼동할 수 있다. 검토 액션과 저장된 상태를 명확히 분리할 필요가 있다.
3. **HWP 환경 미충족:** 필수 회사·기관 값이 없어 Worker 연결 및 실제 생성물 배치 검증까지 진행하지 못했다. 가짜 사업자 정보로 이 조건을 우회하지 않았다.

첫 자동 실행은 선택 상자 탐색 방식 때문에 중단했다. 접근성 역할을 기준으로 테스트 선택자를 수정한 뒤 재실행했다.
앱 기능 통과로 기록한 것은 최종 실제 실행이며, 재검토 문제는 해결된 것으로 표시하지 않았다.

## 증거와 재현

최종 증거 폴더: `data/workspace/sample-loop/E2E-SAMPLES-1788792343320/`

- `result.json`: 실행 단계, 상태, 발견 사항.
- `artifact-checks.json`: 다운로드 파일과 입력값 비교 결과.
- `requirements.xlsx`, `review-package.zip`: 앱에서 내려받은 원본 생성물.
- `review-desktop.png`, `review-mobile.png`: 최종 화면.

예시 시나리오 Playwright: **1 passed (31.9s)**. 타입 검사 및 예시 생성·검증 도구 정적 검사 통과.
후속 기존 작업대 회귀 실행: **4 passed, 1 skipped (33.5s)**. 이때 예시 시나리오는 별도 실행이므로 중복 실행하지 않았다.
이 결과는 차단 조건을 정상 처리하는 경로를 포함하며, HWP 생성 성공을 뜻하지 않는다.

재실행은 `frontend`에서 E2E_BASE_URL=`http://127.0.0.1:3002`, E2E_API_BASE=`http://127.0.0.1:8002`,
E2E_WORKSPACE_V2=`true`, E2E_SAMPLES=`true`로 설정한 뒤 실행한다:

```text
npm run e2e -- --project=workspace-v2 --grep "sample PDFs"
```

예시 PDF는 `tools/create_document_loop_samples.py`로 재생성할 수 있다.
검증 도구 `tools/verify_document_loop_outputs.py E2E-SAMPLES-1788792343320`는 다운로드 결과를 수정하지 않고 대조한다.
