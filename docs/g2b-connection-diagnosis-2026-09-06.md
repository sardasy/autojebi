# 나라장터 API 연결 진단

## 판정

2026-09-06 이 PC에서 API 호스트의 HTTPS 연결이 성립하지 않았다. 문서의 HTTP 주소로 바꿔 실제 인증키를 넣은 최소 요청도 응답 대기 시간 초과였다. 코드의 인증키 로딩은 확인했지만, 인증 응답을 받지 못했으므로 키 유효성/서비스 승인 여부는 미확인이다. 연결 문제가 해결됐다고 판정하지 않는다.

## 첨부 문서 비교

참고: 사용자 제공 `조달청_OpenAPI참고자료_나라장터_공공데이터개방표준서비스_1.2.docx`의 서비스 정보/요청 인자 표.

| 구분 | 첨부 문서 | 현재 autoJEBI |
|---|---|---|
| 서비스 | PubDataOpnStdService | BidPublicInfoService |
| 경로 | /1230000/ao/PubDataOpnStdService | /1230000/ad/BidPublicInfoService |
| 기능 | getDataSetOpnStdBidPblancInfo | 업무별 PPSSrch 5종 |
| 날짜 인자 | bidNtceBgnDt / bidNtceEndDt | inqryBgnDt / inqryEndDt |
| 인증 인자 | ServiceKey | serviceKey |
| 검색 | 공고일 범위, 최대 1개월. 공고명 인자 없음 | bidNtceNm 공고명 검색 |
| 전송 | HTTP, SSL 없음 | HTTPS 기본. 이번 수정으로 명시적 HTTP 선택 가능 |

둘은 서로 다른 서비스다. URL만 표준서비스 주소로 교체하면 요청 인자와 응답 날짜 구조가 맞지 않는다. 첨부 문서가 현재 코드의 서비스 주소 오류를 증명하지는 않는다.

공식 입찰공고정보서비스 안내: https://www.data.go.kr/data/15129394/openapi.do
프로그램을 현재 경로로 사용하려면 이 서비스가 활용신청 승인 상태인지 확인해야 한다. 표준서비스만 승인받았다면 별도 활용신청 또는 별도 표준서비스 어댑터가 필요하다. 이번 변경은 표준서비스 어댑터를 추가하지 않는다.

인터넷 전체 장애가 아니라 이 PC에서 API 호스트까지의 연결/응답 경로 문제로 범위를 좁혔다. 단말 보안, 사내 네트워크 정책, 외부 경로, 제공기관 장애 중 어느 것이 원인인지는 이 결과만으로 특정할 수 없다. HTTP 401/403 또는 API 인증 오류 코드를 받은 것이 아니므로 키를 다시 발급하라고 단정하지 않는다. HTTPS 인증서 검증을 끄거나 보안 설정을 변경하지 않았다.

## 코드 보정

- G2B_API_SCHEME=https 기본, http 명시 선택만 허용. 호스트/서비스는 고정하며 자동 HTTP fallback 없음. HTTP는 인증키가 암호화되지 않으므로 명시적으로 제공기관 계약에 맞춰 설정할 때만 사용한다.
- 연결 8초/응답 30초 제한. 기존 3회 재시도 유지.
- 연결 시간 초과, DNS/TLS 연결 오류, 응답 대기 초과, 중계 서버 오류 구분.
- 오류 22/23(호출 한도), 29(IP 차단), 05(중계 지연)를 인증키 오류와 구분.
- 기본 검색 종료일을 오늘로 수정하여 불필요한 미래 30일 호출 제거.
- 검색 재시도 시 과거 실패 문구가 즉시 처리 중 상태로 전환.
- 인증키 양끝 공백 제거, httpx URL 로그 및 자격 조회 예외 URL의 키 노출 방지.

## 외부 확인 필요

1. 같은 PC에서 다른 허용된 네트워크로 API 접속을 비교한다. VPN/보안 도구는 임의 해제하지 않는다.
2. 네트워크 담당자에게 API 호스트 80/443 경로를 확인하고, 제공기관에는 위 시간 초과 결과로 문의한다.
3. TCP/API 응답 복구 후 입찰공고정보서비스 승인 여부를 확인하고 원래 공고 조회/저장/분석을 재개한다.

## 후속 문서 및 새 인증키 반영

사용자가 추가 제공한 `조달청_OpenAPI참고자료_나라장터_입찰공고정보서비스_1.2 (1).docx`는 현재 클라이언트와 동일한 서비스다. 서비스 정보 표는 HTTP 및 SSL 없음으로 명시하고, 오퍼레이션 14 요청 표는 `ServiceKey`, `inqryDiv`, `inqryBgnDt`, `inqryEndDt`, `bidNtceNm`을 명시한다.

- 새 키를 Git 제외 `.env`에 반영했다. 문서에 맞춰 이 데모의 `G2B_API_SCHEME=http`를 명시 설정했다. 위의 이전 진단 시점과 달리 현재 데모는 HTTP를 사용한다. 코드 기본 HTTPS 및 자동 fallback 금지는 유지한다.
- 인증 인자 이름을 `ServiceKey`로 맞추고, URL 인코딩된 키가 한 번만 디코딩/인코딩되는 회귀 검증을 유지했다.
- HTTP 및 `ServiceKey` 적용 후 2026-08-12~13 물품 공고 `전자파 해석 SW`를 단일 요청으로 재조회했으나 실제 응답은 `ReadTimeout`이었다. 성공 응답이나 인증 오류 응답 모두 받지 못했다.
- 관련 클라이언트 테스트 48 passed(17.87초), ruff 통과. 실검색 복구 및 공고 저장/분석 완료를 의미하지 않는다.
- 인증키는 이 문서와 실행 출력에 기록하지 않았다.
