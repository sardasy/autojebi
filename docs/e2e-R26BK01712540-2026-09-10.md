## 우선 보완 사항

1. **AI 인용 실패의 수정 동선과 진단 정보.** 인용 검증 자체는 유지해야 한다. 이번 실패에서 어느 요구사항·어느 인용이 불일치했는지 사용자 화면에 제시되지 않아 3개를 수동 등록했다. 원문과의 대조 정보를 안전하게 보존하고, 검증된 부분과 실패 부분을 분리해 사람이 수정할 수 있어야 한다. 실제 오류가 공백 차이인지 잘못된 인용인지는 확인되지 않았다.
2. **HWP 문서 열기 안정성.** Worker 작업 `2a9fa15def754023a41dc2d80e2022ff`가 `Open`에서 시간 초과했다. 이후 health는 `worker_recovery`, `available=false`, `recovery_required=true`를 유지했고, 뒤늦게 `Quit` 단계가 표시되어도 차단이 해제되지 않았다. 보안창·파일 잠금·사용자 세션 등 정확한 원인은 미확정. 파일·프로세스·표식을 확인한 명시적 복구 뒤 템플릿 검사부터 재시험해야 한다. 자동 재시도·강제 종료·보안 우회를 하지 않았다.
3. **원문 세트 완전성.** 동일 공고서의 HWPX/PDF가 있다고 상세 제안요청서와 과업내용서를 확보했다고 볼 수 없다. 첨부 목록 완전성과 본문에 참조된 별도 문서의 누락을 분리해 표시해야 한다.
4. **실행기 작업 분리.** HWP 검사 대기 동안 비-HWP 패키지도 대기했다. 장시간 COM 대기가 일반 문서 작업에 주는 영향을 줄이는 실행기 분리가 필요하다. 이번에는 검사 실패 확정 후 패키지가 정상 완료됐다.
5. **결과 메시지.** 상단 마지막 실행 결과가 작업 완료 후에도 `작업 접수 완료`로 남고, 상세 카드에서만 최종 결과를 볼 수 있었다. 마지막 실행 결과와 카드 상태를 함께 갱신하는 것이 좋다.

## 검증 범위와 보존

이번 기록은 실제 브라우저 버튼·실제 G2B·실제 설정 LLM·실제 Windows Worker의 결과다. 테스트 전용 가짜 성공 응답을 주입하지 않았다. UI 후속 확인은 로컬 조회 API와 파일 해시/ZIP/Excel 읽기 전용 검사로 보강했다.

이번 턴에서 전체 pytest, Vitest, mock E2E를 다시 실행하지 않았으며 과거 통과 수를 이번 결과로 재사용하지 않는다. 소프트웨어 검증 조건을 변경하지 않았다. 새 참고자료·초안·원문·실패 이력을 보존하고 모든 파일은 검토 대기 상태로 남겼다. 실제 HWP 생성과 전체 루프 완료는 아직 차단되어 있다.
